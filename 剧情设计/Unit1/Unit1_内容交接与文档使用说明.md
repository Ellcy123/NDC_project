## State 与完整对白的制作顺序（2026-09-17）

1. 三份核心文档按职责共同作为五轮输入；案件方案是 Manifest 的单一大纲入口，其明确引用的核对稿、增强情节线提供配置事实与叙事事实，不另复制一套大纲。
2. 先形成事件覆盖、玩家控制流、跨场衔接和疑点材料归属；新增疑点条件或玩法前置须按项目修改确认规则展示具体方案。已确认的事件不重新设计。
3. 生成五份完整 state 前，先将 Manifest.history 中原位保留的旧六轮 state 安全归档，核对副本并更新历史路径；新文件通过检查后才登记 presentLoops，不能用旧六轮文件冒充五轮产物。
4. 按新版 state，参考工程旧对白，输出 L1—L5 完整对白工作稿。保留、迁移、改写及新增正文全部整合，包含选项分支、探索事件、指证、重复对话与演出备注；不得以“同旧稿”或逐句补丁替代完整正文。
5. 修改索引单独维护旧段落去向与接入关系；对白完整不等于全部重写，不自动回写 JSON、预览配置或 Unity。

## 接手时特别注意

- 本轮是五 Loop 内容。新版五轮位于 `U1优化制作/06_State/`；当前 `剧情设计/Unit1/state/` 已恢复旧六轮；旧《Unit1大纲》、归档六轮 State、正式台本和工程表主要用于核对原物件、地点与既有表现，不能把旧情节重新带回新版。
- 固定开篇、独立AVG、突发事件（进场事件／调查触发事件）、普通问话，按增强情节线开头的场景落位表区分。发生在指证之后的剧情不自动归为固定指证后段。
- 作者知道的真相不等于玩家已经知道。James利用邻病房信息、将威胁纸条塞进清洁间的过程只记作者侧动线，不新增玩家线索、证词或还原台词。
- 故障枪在L4取得后直接于物品详情呈现故障、未见试枪痕迹及故障后未击发；不再设计分析／检查流程，不设检查完成或详情已读前置。L5回用同一物品：未见Tommy所述Webb当面试枪留下的痕迹，确认Tommy编造了这段互动；Webb当时可能已死仍只是怀疑，不能据此直接确认死亡或认定Tommy为射手。James的争枪走火辩解由同一物品详情说明的“故障后未击发”反驳；不把“未见试枪痕迹”简写成“未见击发痕迹”，不新增维修资料。
- 三个环境趣味点已纳入：L2小包厢猎犬面具提醒、L2 Tommy办公室系勺饭盒及爱惜饭盒纸条、L3大厅吧台小酒保私藏的藏酒假书。均可查看、不收集，不额外增加指证材料。

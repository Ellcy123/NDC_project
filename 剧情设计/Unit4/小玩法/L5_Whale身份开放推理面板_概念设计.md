# L5 Whale 身份开放推理面板｜概念设计

> 文档状态：概念方向稿，非定稿运行合同，非精确题库
>
> 场景：Unit4 Loop5，Mickey 私人办公室
>
> 核心目标：让玩家在一张可自由整理的桌面调查板上，亲手重建人物、案件与系统之间的关系；Whale 身份是其中最重要的成果之一，但不是面板唯一承载的结论。

---

## 一、核心体验

玩家面对的不是三道有标准材料数量的题，而是一张已经积累了多个 Loop 信息、但关系仍未被整理清楚的开放调查板。

人物、案件、组织、证据、时间、地点和已知事实都可以成为节点。玩家可以自由移动节点，并尝试在任意两个节点之间建立关系。有效关系会永久保留，系统用一句可读的事实说明这条关系为什么成立，并可能生成一个新的事实节点。新事实节点不是终点，它还可以继续与其他节点连线，逐步形成更高层的认识。

这套玩法允许玩家系统性穷举。玩家即使没有立即看懂，也可以通过不断试连、阅读有效关系反馈、利用新生成的事实继续尝试，最终抵达关键真相。推理感主要来自“我亲手把散落信息织成了网络”，而不是“我猜中了系统预先规定的四个槽位”。

---

## 二、明确不采用的题型

本概念坚决不采用以下结构：

- 不采用“一道问题需要四份指定材料”的配方题。
- 不向玩家显示某个结论需要几份材料。
- 不显示材料清单、空槽数量、完成百分比或“还差一件”的轮廓。
- 不把现行三条身份链直接做成三道题。
- 不把界面切成三栏，让玩家把证据卡分类填入。
- 不要求玩家先猜出系统想问什么，才允许开始整理信息。
- 不因无效尝试扣除材料、清空连线、回退进度或锁死路线。

玩家看到的是一张开放节点网，不是被包装成桌面的固定答案表。

---

## 三、界面草图

整体采用 Mickey 办公室书桌的俯拍背景。桌面、皮质书写垫、台灯、烟灰缸、文件夹和纸张都属于场景的一部分，调查面板像是 Zack 临时把所有信息摊在桌上，而不是突然进入一块抽象科技白板。

```text
┌──────────────────────── Mickey 办公室桌面 ────────────────────────┐
│                                                                  │
│   [人物节点]          [案件节点]                [组织节点]        │
│      Mickey             Harrison                  Tidewater       │
│         ╲                  │                           ╱           │
│          ╲           ┌─────┴─────┐                   ╱            │
│        [新事实] ──────┤ 可拖动节点网 ├────── [时间 / 地点]         │
│                       └─────┬─────┘                                │
│                             │                                    │
│                      [W / Whale]                                 │
│                    身份尚未被实名确认                              │
│                                                                  │
│  [证据节点] [证词节点] [既有事实] [新生成事实]                    │
│                                                                  │
│  ┌─关系说明──────────────────────────┐   [整理视图] [提示] [退出] │
│  │ 玩家刚建立的关系为什么成立，以及它的证明边界                   │
│  └────────────────────────────────────┘                           │
└──────────────────────────────────────────────────────────────────┘
```

布局原则：

- 节点初始按大致语义散落，而非按答案预先排好。
- 玩家可自由拖动节点，形成自己的阅读顺序和空间记忆。
- 不设置三条固定泳道，也不在视觉上暗示“这里有三组答案”。
- `W / Whale` 可以作为早期已知但未实名的特殊节点存在；界面在 Mickey 正式承认前不显示 `Mickey = Whale` 的文字等号。
- 当前选中的关系加深显示，非当前关系可降低透明度，避免线网失控。
- 关系说明区始终使用普通语言解释内容，不能只给绿勾、音效或“连接成功”。

## 四、节点类型

本稿只定义节点类别，不写死最终节点总数、全量名称和全部正确连线。

### 1. 人物节点

用于承载个人身份、行动边界和跨案件出现情况，例如 Mickey、Harrison、Rosa、Morrison、Pierce 等。

人物节点本身不是结论。它需要与证据、时间、组织或新事实产生关系，才形成可推理内容。

### 2. 案件节点

用于把不同 Loop 的调查对象重新放到同一张图上，例如 Harrison 案、圣心医院与 Rosa 相关事件、Morrison 死亡现场，以及其他已调查事件。

案件节点的作用不是重述剧情，而是让玩家看见不同案件之间反复出现的接口、处理方法和责任边界。

### 3. 组织节点

用于承载 Donnelly & Associates、Tidewater、Lakeshore、Pierce 所在的警务网络等系统关系。

组织节点尤其需要区分：谁提供法律壳、谁处理资金、谁执行地面行动、谁位于 Whale 接口之上。不能把所有黑幕压缩成一个“幕后组织”。

### 4. 证据与证词节点

来自玩家已经获得的实物、文件、现场痕迹和正式证词。证据节点可以展开查看原描述，并标出可被引用的事实片段，但不会显示“本证据属于哪道题”。

同一证据可以支持多个不同关系，只要引用的是不同事实维度。证据不会因为成功连线而被消耗或从桌面移除。

### 5. 时间节点

承载年份、来电窗口、案发前后顺序、职责接管节点等信息。时间节点既可与事件相连，也可与文件、人物或组织相连。

### 6. 地点节点

承载办公室、Harold 宅邸、法院、医院等地点关系。地点只能证明它实际能够证明的范围，不能因为某物出现在私人空间，就自动推出其所有者实施了另一地点的行为。

### 7. 事实节点

事实节点分为两类：

- 既有事实：玩家在前序调查中已经明确取得的认识。
- 新生成事实：玩家建立有效关系后，由系统以可读句子生成的中间结论。

新生成事实可以继续与人物、案件、组织、时间、地点或其他事实连接，是开放推理能够逐层推进的关键。

## 五、基础操作循环

1. 玩家观察桌面上现有节点，按自己的习惯移动和分组。
2. 玩家选中一个节点，拖出关系线，再选择第二个节点。
3. 系统判断当前两个节点之间是否存在此时可成立的直接关系。
4. 若关系有效：
   - 连线永久留在桌面；
   - 弹出一句说明关系内容的普通语言反馈；
   - 标明这条关系能证明什么、不能证明什么；
   - 需要时生成一个新的事实节点。
5. 玩家可立刻拿新事实节点继续尝试连线。
6. 若关系无效：
   - 临时线自然退回；
   - 不扣除任何资源；
   - 不清除其他关系；
   - 不影响已生成事实；
   - 该节点对可留下轻微“已尝试”记号，帮助玩家系统性排除重复操作。
7. 玩家不断扩展网络，直到足以支持当面对质的事实集和其他重要重解释达到后台门槛。

基础操作应尽量统一为“移动节点、两两连线、阅读结果、继续连线”，不为不同节点类型额外增加大量专用小玩法。

## 六、有效关系与知识生成

### 1. 有效关系必须产生内容

正确反馈不能只是绿勾或“连接成功”。每条有效关系至少需要给出：

- 两个节点之间具体是什么关系；
- 这条关系依据的事实维度；
- 它当前能证明到哪里；
- 必要时说明不能越过的推理边界。

示意格式：

> 这份文件把匿名资金编号与 Donnelly 的受托账户连接起来。它能证明法律资金接口存在，不能单独证明账户属于某个人私人所有。

这只是反馈格式示意，不代表本稿已经确定具体关系题库。

### 2. 新事实节点应可继续使用

有效关系如果产生了比原始材料更高一层的认识，系统在桌面上生成一张新的事实卡。新事实卡应保留来源回溯：玩家点击后可以看到它由哪些已建立关系支持。

例如，后台现行设计中的资金接口连续性、书写者与参与者视角、近期访客等结论，可以转化为开放网络中的高价值事实节点。但它们在 UI 上不应被预先暴露成三道指定材料题。

### 3. 不替玩家讲完最终结论

关系反馈应说明已经建立的事实，不把后续尚需连接的推理一步讲完。玩家需要亲手把中间事实继续接入人物、组织和案件网络。

在 Mickey 正式承认前，系统不得用文字直接弹出 `Mickey = Whale`。面板只负责形成足以开启当面对质的证据网络与支持事实集，不生成最终身份结论节点。最终实名判断仍由玩家在后续 Expose 中主动完成，Mickey 的承认再作为戏剧落锤。

## 七、穷举可达性规则

允许穷举是本玩法的正式可达性保障，不视为作弊或低级玩法。

### 1. 有限节点集

任一时刻可见节点数量必须有限。玩家可以系统性尝试所有可见节点对，并通过“已尝试”标记避免无意义重复。

原型阶段应把每一阶段的未尝试节点对控制在约 45 组以内；超出时必须分批开放节点、折叠已穷尽节点或缩小当前候选集。`A → B` 与 `B → A` 视为同一组无序尝试，不能要求玩家反向再连一次。

### 2. 无效尝试零损失

无效连线不消耗证据、不扣次数、不清进度、不锁节点、不重置已完成关系，也不触发长冷却。

### 3. 每轮穷举都必须能够产生进展

在当前节点集中，只要仍存在未发现的关键有效关系，完整尝试所有未尝试节点对就必须至少发现一条新关系或生成一个新事实节点。不能要求玩家在两个节点之间选择隐藏的精确像素、不可见关系类型或未提示的拖拽方向。

### 4. 新事实扩大下一轮候选集

生成新事实后，玩家可对“新事实 × 当前所有节点”继续系统性尝试。只要持续扩展并穷举，最终必须能获得支撑身份对质的关键事实，并达到必要剧情门槛。

### 5. 关系有效性保持稳定

同一版本的两个可见节点之间，关系不能一会儿无效、一会儿因隐藏剧情条件突然有效。如果后续信息确实改变节点含义，应明确升级或替换节点，并清除该节点相关的旧尝试标记，让玩家知道候选关系已经发生变化。

### 6. 不依赖唯一操作顺序

除非新事实尚未生成，否则不同有效关系应允许以任意顺序发现。后台可以有依赖层级，但不应把玩家强制锁进一条固定解题顺序。

## 八、无效关系、提示与卡关保护

### 无效关系反馈

无效关系的基础反馈应短而中性，例如：

> 目前没有足够信息建立这条直接关系。

它不应嘲讽玩家，也不应弹出“错误答案”大字。连线退回后，节点仍可继续使用。

如果两个节点确实相关，但中间还缺事实，可使用不泄露答案的反馈：

> 两者可能处于同一事件范围，但现在还缺少能把它们直接连接起来的事实。

这类反馈不能意味着同一对旧节点会在隐藏条件满足后突然变为有效。中间事实生成后，玩家应连接“新事实节点 × 原节点”；旧节点对仍保持原判定。

### 提示层级

提示只缩小搜索范围，不直接报出正确节点对：

1. 长时间无新关系时，提示玩家优先检查某种关系维度，如时间、账户控制、行动地点或组织职责。
2. 多次无效尝试后，可轻微强化一组仍有未发现关系的节点区域，但不画答案线。
3. 玩家主动请求进一步提示时，可说明“当前有一个新事实可以由某类节点关系生成”，仍不列出指定材料清单。
4. 最强提示可以暂时隐藏已经穷尽的节点对，让剩余可尝试范围变小，但不自动连接。

提示系统不得显示“还差 X 个槽位”或“请放入某四份证据”。

## 九、完成层级

开放面板不使用一条显眼的三题进度条，而以知识网络的状态形成多个完成层级。

### 层级一：局部关系成立

玩家发现人物与证据、案件与时间、组织与职责之间的直接关系。每条关系永久保留，并提供可读反馈。

### 层级二：高价值事实生成

多个局部关系产生可继续使用的新事实。玩家开始重新理解已调查过的案件，而不只是整理孤立证据。

### 层级三：跨案件与系统关系重解释

面板需要能够承载对 Harrison、Rosa、Morrison 等过往事件的重新阅读，并逐步呈现 Donnelly、Tidewater、Lakeshore、Pierce 等人物与组织在系统中的不同位置。

这里的目标不是把所有案件写成同一人直接下令，而是让玩家看见：有些行动经过 Whale 接口，有些行动由上层绕过接口，有些帮助真实发生，但被控制在可牺牲的执行层。责任边界必须保留。

### 层级四：达到 Whale 对质解锁门槛

Whale 身份是开放网络中的重要成果之一。后台仍可参考现行三条身份链所要求的核心证明维度与完成门槛，判断玩家是否已经建立了足以开启当面对质的支持事实。

但前台绝不能把这些后台条件显示成“三道题、九个固定槽、每题指定材料数”。玩家应感觉自己是在整个关系网中自然抵达身份判断。

达到门槛后不立刻强制切断桌面。界面解锁“开始对质”，由玩家主动确认后再进入 Mickey 返回与后续 Expose；确认前仍可继续整理 Harrison、Rosa、Morrison 等旧案关系。面板中已发现的其他关系应保留为玩家对全章系统的理解，而不是在对质解锁门槛满足时被视为无关支线。

面板的完成反馈只说“已经具备当面对质的依据”，不提前宣布实名结论。后续 Expose 的职责是让玩家用这些支持事实逐轮击穿 Mickey 的狡辩并亲手完成最终身份判断，不应要求玩家原样重做整张关系网。

### 节点准入与时序边界

面板只允许使用进入 4042 前玩家已经获得的信息，以及 4042 办公室内在 Mickey 回场前合法取得且当前可读的内容。

- `4516 Miller保险外卷与内封套` 此时最多呈现外卷内容与封套外观，内封仍保持不可读。
- `4517—4519`、Sean 页、水源页、投毒、小 Charles 等非 Loop 终幕信息不得进入面板，也不得通过关系反馈或新事实节点提前生成。
- L4 已知的 Patrick 事实可以进入面板，例如“不知姓名便折返”“没有临终交接”；但不得生成“Patrick 选择 Mickey 为继承人”或“把使命交给 Mickey”的事实。那只能是 Mickey 在身份承认后的个人解释，不参与对质解锁门槛。

## 十、内容扩展方式

本稿暂不写死具体全量节点和正确连线。后续扩充内容时，优先增加以下数据，而不是增加新的固定题框：

- 新节点：人物、案件、组织、证据、时间、地点、事实。
- 新有效关系：定义两个节点为何能够相连。
- 新关系反馈：用白话说明关系内容与证明边界。
- 新事实生成规则：有效关系生成什么中间认识。
- 新事实的后续关系：它还可以与哪些节点继续连接。
- 关系来源回溯：新事实由哪些关系支持。
- 剧情门槛标签：哪些高价值事实共同满足身份或事件推进条件。

内容设计时应把“关系成立”与“最终结论成立”分开，避免一条线直接跨越多个推理层级。

具体节点规模、关系密度、初始摆放、分批显示方式、正确关系全集和提示文案，都需要在后续原型与玩家测试中确定。

## 十一、与现行 State 合同的方向差异

当前 `loop5_state.yaml` 的 `identity_lock` 运行合同采用：

- `lanes: parallel`
- `slots: fixed_per_chain`
- 三条身份链分别完成
- 玩家主动提交
- 三链全部完成后触发 Mickey 返回与 Expose

本概念只保留其中“玩家主动建立证明”“无效尝试不消耗、不清已完成进度”“达到后台对质解锁门槛后触发后续剧情”等原则。

开放节点网与 `fixed_per_chain` 存在明确方向差异：

- 前台不再有三条可见泳道。
- 不再有每链固定材料槽。
- 不再向玩家暴露每条链所需材料数量。
- 中间事实可以跨原有链条继续连接。
- 对质解锁是整个知识网络达到后台条件后的结果，而不是三张答题卡分别盖章。

因此，本概念不能直接被视为现行 State 的 UI 换皮。真正实施前，需要另行讨论并修改特殊机制规范、State 合同、校验逻辑与运行适配方式。

本次只创建概念设计文档，不修改现行 `state`、特殊机制规范、验证器或配置表。现行三条身份链仍是当前 canon 运行合同，本稿在正式迁移批准前不替代它。

## 十二、主要风险

### 1. 节点组合数量膨胀

节点过多时，两两组合会快速增长。需要通过分批出现、语义分区、自动淡化已穷尽节点和视图整理工具控制规模，但不能重新退化成指定槽位。

### 2. 关系线过度拥挤

应支持拖动节点、折叠次要关系、只高亮当前路径、按案件或组织筛选。任何自动整理都不能改变玩家已经建立的关系。

### 3. 有效反馈写得过于抽象

如果反馈只有“存在联系”，玩家即使穷举成功也无法理解推理。每条有效关系都必须说明事实内容和证明边界。

### 4. 穷举变成纯机械劳动

允许穷举不等于鼓励无脑点遍所有组合。节点描述、空间摆放和关系反馈需要不断给玩家新的理解，使玩家在穷举过程中逐渐开始主动预测下一条关系。

### 5. 新事实节点无限增殖

需要控制推理层级和事实颗粒度。只生成能够参与后续关系或帮助理解系统的重要事实，不为每条普通描述都制造新节点。

### 6. 提前泄露身份

网络可以让玩家建立足以开始对质的支持事实，但 UI 在 Mickey 承认前不得直接显示实名等号、生成最终身份结论节点，也不能让 Zack 用旁白替玩家宣布最终答案。

### 7. 责任边界被网络视觉压平

把节点连在一起不等于它们承担相同责任。关系说明必须持续区分实际控制与法律所有、访客与枪手、Whale 接口与 Miller 上层、真实帮助与代价分配。

### 8. 实现成本高于固定配方题

开放关系网需要关系数据库、事实生成、来源回溯、节点状态、尝试记录和图形整理能力。应先做低成本交互原型，验证拖动、连线、反馈和穷举是否成立，再决定完整制作范围。

---

## 十三、验收原则

概念原型至少满足以下条件，才算真正实现了开放推理面板：

1. 玩家看不到三道题、固定槽位、材料数量或指定材料清单。
2. 人物、案件、组织、证据、时间、地点和事实都可以作为可移动节点。
3. 玩家可以自由尝试任意两个当前节点的连线。
4. 有效关系永久保留，并用完整句子说明关系内容和证明边界。
5. 有效关系能够生成可继续连线的新事实节点。
6. 无效关系不消耗、不惩罚、不清除任何已完成进度。
7. 玩家通过系统性穷举一定能够获得新事实并最终达到关键剧情门槛；每阶段未尝试节点对控制在约 45 组以内，且连线方向不构成第二次尝试。
8. 同一证据可以在不同事实维度中被重复使用，不受“一证据一题”限制。
9. Whale 身份是重要成果，但面板同时能重解释过往案件和系统关系。
10. 三条现行身份链只作为后台证明维度参考，不在 UI 还原成三题九槽。
11. Mickey 承认前不出现文字形式的 `Mickey = Whale`，面板只解锁“开始对质”，不代替后续 Expose 完成实名证明。
12. 原型明确标注其与现行 `fixed_per_chain` State 合同不兼容，未经另行批准不得直接替换运行合同。
13. 对质解锁门槛满足后由玩家主动决定何时开始对质，确认前仍可继续整理旧案关系。
14. 正式节点表必须通过闭包检查：从初始节点出发，不猜关系类型、不依赖连线方向，反复枚举可用节点对，能够生成全部必需事实并抵达剧情门槛，不得存在循环依赖卡死。

---

## 十四、后续工作边界

如果概念方向继续推进，下一阶段应先制作不绑定正式内容的交互原型，用少量占位节点验证：

- 自由移动是否顺手；
- 两两连线是否容易理解；
- 有效关系反馈是否足够有信息量；
- 新事实继续连线是否形成自然的推理节奏；
- 单阶段候选规模是否能控制在可穷举范围；
- 从初始节点到剧情门槛的关系闭包是否完整且无循环卡死；
- 系统性穷举是否确实可达且不令人疲劳；
- 图面在节点增多后是否仍可阅读。

原型验证通过后，再单独设计正式节点表、有效关系表、事实生成表和剧情门槛，并另开变更流程调整特殊机制规范与 State。本文不提前锁定这些精确内容。

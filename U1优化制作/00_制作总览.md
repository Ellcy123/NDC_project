> 建立日期：2026-09-17。用途：组织新版五 Loop 的增量美术需求、对白迭代与配置接入。
> 当前阶段：目录结构与需求标准已确认；已建立总览、工程基线与变更总账及场景背景需求初稿。场景新增布局待审阅，完整视觉复用验收、其他类别需求及工程接入尚未完成。

## 一、范围与来源

本次目标是在工程现有 U1 上落实已确认的五 Loop 设计，明确哪些内容保留、迁移、修改、新增或停用。覆盖场景背景、证据与环境物、场景人物、角色表情、动态漫画、真相还原，以及关联对白和配置。

| 判断内容 | 采用依据 |
|---|---|
| 当前对白、入口、条件和资源引用 | 用户指定的工程 `D:/NDC` 当前配置；对白以 `Assets/table/Talk.json` 为基准，并核对相关配置及实际运行表 |
| 新版案件与推理目标 | [双重谋杀计划与欠条版](../剧情设计/Unit1/Unit1_内容修改方案_双重谋杀计划与欠条版.md) |
| 场景、NPC、材料与取得条件 | [逐 Loop 核对定稿](../剧情设计/Unit1/Unit1_逐Loop场景人物证物与指证核对定稿.md) |
| 人物关系、事件顺序与演出 | [增强情节线](../剧情设计/Unit1/内容修改后的增强情节线.md) |
| 来源分工与已确认补充 | [内容交接与文档使用说明](../剧情设计/Unit1/Unit1_内容交接与文档使用说明.md) |

工程确定现状，新设计确定目标。策划库现有 AVG 与完整台本用于对照，不覆盖工程后续修改；旧大纲、六轮 state 和旧需求中的剧情安排不能自动带入新版。Manifest 尚登记旧六轮来源，本总览不表示其已迁移，也不把 U6 五轮试验配置当作 U1 正式基线。

每轮实际迭代记录工程版本、相关未提交修改及所用文件指纹。保留原对白和资产应有明确判断，不预设整章重写或整套重做。

用户确认：沿用之前美术需求文档的细致程度。写到美术能明确知道画面、人物动作、证物内容和交付目标；不只列名称、情绪标签或一句“按新版修改”。

| 参考文档 | 参考其表达方式 |
|---|---|
| [Unit1 最终美术需求](../剧情设计/Unit1/美术需求/Unit1_最终美术需求.md) | 按场景说明开场在场者、位置姿势、中途进退场与关键动作 |
| [Unit1 人物表情需求](../剧情设计/Unit1/美术需求/Unit1_人物表情需求.md) | 写清眉眼、视线、嘴部、姿态及情绪强度，关联具体资源 |
| [Unit4 场景底图悬浮格需求](../剧情设计/Unit4/美术需求/Unit4_AVG突发事件动态漫画与闪回需求_场景底图悬浮格版.md) | 逐格写唯一画面信息、底图状态、位置避让、挂载内容及普通 AVG 承担的部分 |

这些文档只作为细致程度与组织方式的参考。旧剧情、旧时间、旧数量、旧路径、测试版本和资源批准状态须另行核对，不能照搬。尤其旧真相还原中的身份动机、烧节目单等内容不作为新版事实。

### 每项需求的共同内容

| 栏目 | 内容标准 |
|---|---|
| 使用位置与目的 | Loop、场景、事件及玩家此刻应获得的视觉信息 |
| 基础需求 | 最终成品的完整要求；单独阅读即可理解，不依赖读者自行拼接旧稿 |
| 工程现有资产 | 核实过的文件、当前用途及必要参考图；尚未核实明确标记 |
| 复用判断 | 原样复用、局部修改、重新制作或本版停用，并说明理由；待核实不得冒充可复用 |
| 具体修改 | 分别说明保留、修改和新增的部分；原样复用项明确无需改图 |
| 状态与关联 | 前后状态、跨 Loop 使用、同物不同视图与其他资产必须一致的特征 |
| 信息边界 | 必须清楚可见的信息，以及此时不能出现的答案、身份或后续情节 |
| 交付与验收 | 产物、规格、命名、关键可读性与一致性检查；未确定规格不随意填值 |

### 各类需求的专用内容

| 类别 | 进一步写清 |
|---|---|
| 场景背景 | 布局、机位、建筑、通道、光照及人物／道具所需空间；独立道具及其状态不计入底图制作 |
| 证据与环境物 | 准确票面文字、可见特征、取得方式、容器关系、查看／分析前后状态及所需产物 |
| 场景人物 | 姿势、朝向、视线、手持物、遮挡、阴影、驻场与进退场状态 |
| 角色表情 | 使用情境、面部和身体表现、强度、适用对白段落及现有表情的复用限制 |
| 动态漫画 | 逐格动作、构图、底图、动静方式、触发位置、声音、停留和退出；不默认每格都制成视频 |
| 真相还原 | 逐段还原事实、此时可揭示的信息、镜头与旁白／字幕、旧画面的复用或替换范围 |

对白未定稿时，漫画先关联事件与动作节点；定稿后补准确触发句，不凭空编造正式 Talk ID。唱片相关需求须核对当前 U4、U5 来源，统一实物形态、跨章识别与试听表现后再定稿。

## 四、组织与复用

- 场景、证据、场景人物和漫画按 Loop → 场景组织；表情按角色集中；真相还原按播放顺序组织。
- 同一资产只维护一份完整需求，其他场景引用；不同状态分别列明，避免每轮重复生产同一物件。
- 基础需求、复用判断和具体修改同时保留。现有文件存在，不自动表示符合新版或已经通过视觉验收。
- 本版停用的旧入口和资产用途进入总账；停用不等于删除工程文件，需检查其他消费者。
- 需求文档先以 Markdown 维护；需要人工交接时再按定稿导出，避免手工维护内容不同的多份正文。
- 新目录存放文档、索引和必要的小型核对资料；图像、视频候选及 PSD 过程文件按[美术生产工作区](../docs/美术生产工作区.md)进入项目外受管目录。

## 五、逐项推进

1. 建立本总览，固定结构与细致程度。
2. 整理工程基线与变更总账，明确已有内容、新目标及复用核查范围。
3. 按场景逐项讨论和细化，再写入对应需求文档；场景布局、人物动作、漫画分镜等制作设计由助手完成，改变既定剧情含义的方案另行展示确认。
4. 基于工程对白按段迭代，将受影响的表情、漫画、配音与视频关联回需求；不等待全章对白完成才开始所有独立资产工作。
5. 对完成的批次准备配置接入与验收，工程写入沿用专门授权流程。

当前完成：本总览、[工程基线与变更总账](01_工程基线与变更总账.md)初版，以及[场景背景需求](02_美术需求/01_场景背景需求.md)初稿。场景稿覆盖 19 个场景母项，另为 2 项道具观察详情保留空间接口（不计背景制作量），包含医院布局提案、复用候选与具体修改，不代表图片或视觉验收完成。后续按用户要求一次处理一项，不同时铺开全部设计议题。

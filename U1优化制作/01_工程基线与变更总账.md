规则：

- 本文的条目编号是制作追踪编号，不是新配置 ID；新增正式 ID 暂不分配。
- “保留”表示设计内容保留，不等于图片、声音和视频已经验收可复用。
- “迁移”也要改入口、人物、时序和关联对白，不只是移动文件。
- “停用”表示新版不再使用该入口或用途，不授权删除工程文件。
- 下表“现有锚点”中的 ID 以工程同名配置表区分；不能把相同数字的地点、道具和场景视为同一条记录。
- 未逐项核实工程挂载的新增演出，以“新版新增安排”记账，不声称工程完全没有相似素材。
- 全文按制作单元归并，详细子资产、逐句对应和最终工作量在各需求文档中展开。

已有反向同步的提交证据：2026-08-10 的 7cb852d0b61238b71140759f380b439d4ebde80f（“chore: 同步章节迁移与配置更新”）包含 EPI01 清单、完整台本与重建工具；清单记录来源为工程 Talk.json。这支持“曾从工程反向合入”的判断，不推断是哪位操作者手工完成了全部过程。

结论：可以复用这批对白作为底稿；今后冲突时仍以最新工程对应记录为旧版基准，而不是把这 1690 条永久冻结为唯一正确版本。

### 2.3 资源与运行机制边界

- U1 正文集合中可识别 28 个 script=6 漫画节点，引用 60 个不同静态图路径；工程 EPI01 静态图目录也有 60 张 PNG。这些是旧版盘点线索，不是新版需求数量，也不是完整美术资产总量。
- 工程 U1 LocationConfig 范围没有医院地点记录。因此医院需要新增 U1 场景接入；是否能借用其他章节的医院背景，须另查资产，不能直接判为所有画面从零制作。
- 工程已存在漫画图片、文本、位置、入场方式、延迟及可选视频的实现。一条现有漫画节点按一格处理，不能把第二个参数误当第二格。新版逐格演出仍需落实切换、字幕和声音。
- 工程存在入场对话触发、分支解锁等实现，但新事件的“一次性、前置条件、跨场景状态、读档恢复”还未逐项验证。类里有字段不等于新版逻辑已经可直接接入。
- 角色和表情索引可用于查找候选来源，导入记录不等于用户批准。所有复用结论以实际文件和视觉核查为准。

## 六、如何维护本账

1. 后续每份需求引用本账条目编号，同时给出完整基础要求，而不是只写“按新大纲修改”。
2. 逐图检查后，记录真实旧资源路径、可复用理由、修改范围与用户确认版本；只有此时才从“候选”变成具体复用结论。
3. 对白段落映射从工程原句开始，列“原样保留／局部改写／迁移改写／新增／停用”，新增先写工作稿，不伪造已存在 ID。
4. 设计有变化先更新权威设计来源，再更新本账及受影响需求；本账不建立第二套剧情真源。
5. 接入后按条目验收；“文档已写”“美术完成”“配置写入”“运行通过”分别记录，不能用一个完成勾选覆盖全部。

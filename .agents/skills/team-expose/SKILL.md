完整指证的设计与重构入口。轮数由独立成立的谜题决定，允许一轮完成有限突破，不默认三到四层，也不套用“事实矛盾 → 物证逻辑 → 物理排除”的固定顺序。

## 先读取真实题目

从仓库根的 `canon_manifest.json` 定位目标版本，读取对应大纲、State、当前 AVG / 台本及人物资料。另读 `docs/游戏系统/核心玩法/指证系统.md`；涉及疑点与材料取得时读对应系统规范。

- 现有题目以实际被挂载的步骤、被驳证词、完整退守段和提交前玩家已读材料为依据；不把文档示例或 State 的 PASS 注释当成验收结论。
- 对照物品 / 证词的正文、摘要、美术需求及分析 / 合成结果。说明材料具体写了什么，不能只有“R2 主力”“证明有罪”等用途标签。
- 分开记录玩家已知材料和实际可选卡池。审查全部已知材料的逻辑作用，再核查可选池是否把合理提交判错；不默认后轮材料在前轮不可见。
- 新设计的谎言与关键证据正文必须具体到可以试打；缺失事实标为待定，不用想象补成 PASS。

首次设计或重构时读 [案例参考](references/expose-examples.md)。只提炼标注的优点，不把整场旧指证视为合格模板；修改过的来源须重新核对。

## 先过硬门槛，再评趣味分

以下问题不能靠总分抵消。任何一项未通过，方案均不得标为可落地；可以向用户说明问题与修订方向。

### 1. 每轮只有一个明确的待反驳断言

写清 NPC 否认的事实、人物、时间、范围和限定词。证词卡、暂停句及紧邻退守对白共同构成题面：不能只挑最窄的一句验收，却让 NPC 在前一句声称“我完全无关”。

不同维度指不同的可验证事实，不是不同道具类型。同一个载体的不同痕迹可以回答不同问题；换成信件、照片、账本也可能仍在反驳同一个大命题。

### 2. 后轮答案不得提前击穿前轮谎言

对每个前轮断言，逐一试交后轮的单件材料、完整答案组，以及它们与当时已知事实 / 材料能构成的合理组合。若已经足以反驳，则属于跨轮替代答案，不能因“不在预设轮次”判错。

- 试打只使用该轮提交前玩家已知的事实，不能借用尚未发生的后轮供述补前提。若必须经前一轮承认才能建立联系，写明新增的必要前提。
- 同样检查前轮答案、旧 Loop 材料及其他来源能否替代本轮答案；NPC 已撤回的旧说法不能充当本轮仍在坚持的谎言。
- 判定分为“足以反驳 / 仅增加怀疑 / 无关 / 缺信息待核”。只证明动机、到访或证人可疑，不自动证明行为、杀人或某个客观时刻。
- 对重点易混材料写一句具体的拒绝理由：它能证明什么、还缺什么。不能使用“还没到这一轮”“不是这组证据”；能写出失败对白也不自动代表逻辑成立，仍须核对材料原文。
- 同一事实的证明效力必须前后一致：不能前轮贬为无关，后轮却靠同一意义定案。

### 3. 标准答案本身充分，且每件都必要

先写出标准答案如何反驳原句，再做减件检查：拿掉任意一件后，缺少哪一环？检查单件、子集及其他合理替代组合。单件足够就不硬凑双件；单件都很弱，也不能因此认定组合充分。

区分玩家必须选择的材料、已知前提、剧情自动展示的补强材料。按完整语境判断必要性；若自动展示的材料已经让玩家选择变得多余，也要调整设计。不能把两个可独立否定的断言拼成一句，强迫玩家填两个槽位。

### 4. 击穿范围与退守连续

成功对白只确认本次已证明的事实。到访不等于杀人，书信表达不等于双方真实内心，物件接触不等于教唆；后续供述产生的新信息须与物证已证明部分分开。

NPC 承认被击穿的一项，再主动保住其他辩解空间；新谎言不得否认刚承认的事实。Zack 可以确认对方说法，不替对方喂出下一轮否认。轮次增加应带来新的问题与必要证据，不只是情绪更激烈。

### 5. 时序与玩法可落地

首个 Lie 对应普通 Talk 已收集的谎言锚；后续 Lie 是 Expose 当场退守，不提前当成普通 Talk 证词收集。每个需要出示的物品 / 证词均须进入当前或更早的疑点 / 碎片 condition，取得时间与实际可选状态允许本轮提交。谎言锚与用于击穿的材料须区分。

发现跨轮抢答时，优先收窄真实题面、调整证据内容与分工，或合并轮次；修改后重跑矩阵。不得临时隐藏合理答案、延后发放本应已收齐的材料，或仅靠程序拒收维持顺序。影响剧情 / 证据链的修改按用户确认范围执行。

## 趣味加分项：在指证中发现证据的新用途

推荐让玩家在自由探索阶段获得事实，在指证的谎言与主动退守语境中重新理解已有证据，产生“原来这个证据还能这样用”的顿悟。证据的关键细节提前可见，探索阶段尽量不由物品描述或 Zack 的对白替玩家解释完用途与结论；新的指证语境让玩家自己发现旧细节的证明价值。

这是优秀设计的加分项，不是硬门槛，也不要求每场或每轮指证都达到。难以自然实现时，玩家在探索阶段已经理解证据用途，甚至推知本次指证要揭示的真相，也完全可以接受，不因此判定设计不合格或要求返工。不要为了制造意外而隐藏必要信息、在提交后才补出关键属性、强造歧义，或牺牲推理的公平性与逻辑。后续 Loop 尚不该揭示的信息仍遵守原有知识边界。

设计与审查时可说明哪处谎言或退守让哪个已有细节产生新用途；没有自然的顿悟点时如实说明即可，不强行补造。本项不改变前述跨轮替代答案与最小证据组的硬门槛。

## 方案必须附的检查材料

每轮附一张简短题目卡：完整待反驳断言、提交前已知前提、标准最小答案与推理、成功后承认的事实、下一次主动退守。答案引用真实材料正文；新增材料给出具体草案。

附“谎言 × 材料”交叉矩阵，每个非对角项给出判定与理由，不仅写标准答案所在的对角线。材料列覆盖后轮答案、前轮 / 旧材料及易混替代组合；必要时拆表，不能只凭道具名称排除候选。

| 待反驳断言 | 标准答案为何成立 | 后轮材料 / 组合试打 | 前轮与其他材料试打 | 减件后缺什么 |
|---|---|---|---|---|
| 每轮填写完整断言 | 已知前提 → 材料事实 → 矛盾 | 逐项判定及理由 | 逐项判定及理由 | 每件的必要作用 |

矩阵底稿保留：确定的替代答案、证明不足、条件风险、未核实的材料与原因。缺信息时给出待核项，不把未完成审查写成唯一性通过。

## Pipeline

用户只要求评价 / 审查时，读取并输出诊断及方案，不执行写入和对白生产。用户已指定具体改法时沿已确认方向修订，不重新强制盲产和选方案。完整新设计按以下流程执行。

### Phase 1：盲产双方案与唯一性检验

并行 spawn 两个 `expose-designer`，相同输入、互相不可见，各产一版方案；不让单个 agent 一次生成多版。提供目标 Loop 来源、材料原文、知识边界、已有设计、本文硬门槛、趣味加分项与检查材料要求，明确趣味加分项不作为通过或返工条件。

每版先过硬门槛，再过指证设计师的五层质检。若两版雷同，让其中一版改变主攻维度；用户已固定的事实和预算不随之改变。主模型复核矩阵，展示通过方案的分歧、关键谎言及材料。若没有通过版本，说明具体缺口，不用补写不存在的事实凑方案。

用户尚未选择时，请其选定具体方案；新增或改变剧情含义的部分先展示真实“改前 → 改后”或新增草案，获确认后写入。已有授权不重复索取。

### Phase 2：State 写入

将已确认方案、矩阵、现有 State 路径和允许修改范围交给 `state-architect`；明确文件责任，告知其他代理可能同时工作，不撤销他人修改。更新 expose、相关 evidence / testimony / doubt 引用，保留材料的证明范围、取得时序和动态谎言语义。

主模型核对写入是否与方案一致。不得在写入时自行扩大已确认范围；新增实质变化先展示并确认。

### Phase 3：Expose 对白

按仓库根 `.codex/skills/ndc-dialogue/SKILL.md` 执行：当前窗口模型控信息、写完整初稿和润色提示词，由 NovAI `[次]gemini-3.8-flash` 润色，主模型核对事实与结构；用户当次指定流程优先。

把每轮断言、证据证明范围、必要前提与失败理由纳入信息边界。核对最终对白的整个退守段，防止润色扩大谎言或提前透露答案。Unit1 仍按完整台本 Phase 1 / Phase 2 规范，不自动回写 JSON、预览表或 Unity。

### Phase 4：完整指证的并行审查

此阶段用于完整谜题设计 / 重构的团队审查；普通对白润色遵循 ndc-dialogue，不因涉及 Expose 自动开启团队。

- `dialogue-reviewer`：独立核对最终题面、证词和材料是否一致，成功对白是否越界，NPC 是否主动退守。
- `player-simulator`：从真实已知信息和可选池出发，独立试打全部后轮答案、旧材料及合理组合，执行减件检查；不能只沿预设正确路线走。
- `timeline-auditor`：核查材料取得、疑点 condition、动态谎言与各轮知识前提的时序。

先让审查员依据原文独立给出判断，再与设计矩阵对账。凡对白、谎言或证据内容发生实质变化，复验受影响行列与组合，不沿用初稿 PASS。

### Phase 5：汇总交付

主模型汇总通过项、问题、矩阵与修订结果。仅在设计分歧无法解决或触及核心原则 / 质量门槛时交 `content-director` 裁决。评分不能推翻硬门槛失败；未解决项必须明确保留。

# MJ operation loop

1. Accept the v4 handoff, current upstream asset lookup and passing reference/handoff visual evidence. Reuse valid evidence under [production-record.md](production-record.md); a text-only draft is not visually cleared. Resume the stable scene/view/state jobs and existing generation reservations before interacting with the browser. Reused approved views satisfy coverage without new jobs.
2. Reuse the suitable Alpha Imagine tab in the intended browser/profile. On a browser/profile change, verify the target MJ account by visible identity before prompt entry or reference attachment; capture the identity and browser/profile in the round record. Browser-switch authorization does not authorize a different account. Reuse an already verified current identity; ask only when it is missing or mismatched. If login is required, have the user sign in to that target account; never inspect credentials/session stores or silently switch accounts.
3. Identify both mandatory saved images against the local assets and assign Style Reference only. Inspect roles, not just thumbnail count. Do not reupload the bundled copies. Additional authorized references use documented upload capability and their declared roles.
4. Verify the latest exposed model unless the user chose a specific one, HD if available, generation ratio 2:1, exact prompt and no stale conflicting image/ratio pills. Keep personalization, speed and unrelated settings.
5. Reserve each image-producing action in the persistent job before submission. Submit once per missing/redraw view and capture job identity, actual prompt/settings and cumulative round. On timeouts mark outcome uncertain and inspect gallery/job history before any new submission; absence of a tool response is not evidence of no job. Wait for the complete grid.
6. Coarsely judge all four against hard camera, spatial topology, routes, major massing and figure-leakage requirements. Record concrete rejection reasons and stop checking a vetoed candidate; fine style/texture not inspected stays NOT_CHECKED and does not block reviewing another candidate. This coarse shortlist is not formal visual PASS. Deferred props are not required.
7. If one is structurally usable but has a small rendering defect, try Vary Subtle then Vary Strong as needed. If the entire grid repeats a structural mistake, repair the smallest relevant prompt delta and resubmit. Do not vary an unusable spatial layout. Whole-frame texture inflation starts again from the original contract and approved refs rather than varying the noisy source.
8. Every actual initial grid, Vary or corrected resubmission consumes one of the default three rounds for that scene/view/state job, including the first. Resume cumulative reservations across prompt changes, browser recovery and task handoffs. An unresolved submission reserves capacity until reconciled; browser observation/retrieval retries consume no generation round. Use production-record commands for persistence, not an independently reset counter. Preserve accepted views.
9. Download a shortlisted native image to work-process storage for original-resolution QA. Check shared architecture and state against source authority and accepted views. Complete whole-image and overlapping-tile review, stage and texture records, actual dimensions and hashes. Selection/copy/delivery may reuse this evidence only with valid current bindings; rejected historical grids remain history. Browser previews alone do not establish file delivery.
10. Deliver each passing native MJ image with prompt/job/settings and review evidence. Stop at MJ delivery. If hard failures remain after budget, report the best available work-process candidate and failure; no hidden extra jobs or promised repair to disguise a failed layout.

Actions: `deliver-native-mj`, `continue-next-view`, `vary-subtle`, `vary-strong`, `repair-and-resubmit`, `budget-exhausted-candidate`. There is no Photoshop/Firefly action in this loop.

## Bounded browser recovery

Keep the intended account, specific browser/profile, tab and last known job identity. When page observation fails, try one fresh tab attachment if the tool reports a stale/unattached session, then one documented alternative observation method if available. If the page is still unreadable, record the actual error and stop browser mutations pending reconnection; repeating the same failing reads or opening more tabs is not progress. Do not change browsers/profiles without the user's authorization.

A visible tab title or URL cannot prove account identity, settings, submission success or generation completion. If submission may have happened, mark its outcome unknown and reconcile the gallery/job history after control returns before sending anything again. Do not count browser retries as new generation rounds or claim zero jobs when submission is uncertain. Normal bounded polling of a readable, confirmed running job may continue; a read timeout alone is not an MJ generation failure.

Record the target and verified identities separately, the last confirmed action, confirmed/uncertain job count and the condition needed to resume. Preserve the ready prompt, persistent reservation, current requirement/source bindings and review records so reconnection continues the same attempt. A new task title, tab, output folder or operator is not a new budget. Resolve uncertain outcomes by matching actual job identity and prompt/settings before releasing a reservation as confirmed-not-submitted or recording a completed round.

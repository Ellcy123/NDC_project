# 资产派生细则

所有共享路径从 `../../ndc-generate-characters/` 解析。只读当前分支，不为状态变体装载MJ搜索或整套动画规则。

## 角色卡与状态

普通卡的身份来自当前批准通用风格全身；已有角色则使用当前批准角色卡。锁定默认整卡提示逐字导出，并按共享 `chatgpt-web-character-generation.md` 的 `general-character-card / default-whole-card` 合同在受支持的内置 `iab` 或外置 Chrome/Edge 中通过网页版 ChatGPT 生成；保持网页原始艺术像素，通过后再规范尺寸与背景。表情／便携剧情道具若未被明确设为当前硬要求，不得导致重开身份设计。

完整角色卡要求正面、严格侧面、背面全身及规定头部／穿鞋／有身份意义的细节；完整双臂自然下垂、双手空置，便携道具只作独立细节。不要用无意义衣料切片补位。需要模块化时遵循对应合同，不通过的模块只阻断依赖它的对象。

只补某张模块时，任务范围仅包含该模块及其真实源依赖，并使用 `general-character-card / modular-component` 网页合同。例如已批准正面/侧面均现成而只缺背面：冻结并引用批准身份源与正面，生成 `fullbody_back`；侧面只在提供额外设计证据时引用，不重做正面/侧面，不自动生成三头部、鞋或细节，不拼整卡。必要的同源后脑裁片作为过程身份证据保留，不等于自动增加正式 `head_back` 交付。单模块使用其约定或现有同组规格，不套整卡2K/4K横画布。

单模块/单次状态通过真实阶段视觉记录、适用风格纹理门禁、尺寸/模式/主体完整/边缘/缩放的实测和持久记录的当前范围检查交付。当前 `audit_character_delivery.py` 与 `validate_delivery_receipt.py` 仅支持card/portrait，不向它们传假类型或伪造整卡回执；只有真实整卡/肖像输出才运行其专门布局/回执门禁。背面正脸五官标为本视图不可见并继承批准身份依据，本图只验可见后脑/耳位/后领/体型/服装结构，不要求回头露出正脸。

单次状态从批准角色卡变更被请求的表情、动作、损伤、道具或服装差分；其余身份、体型、配色、服装构造与画风冻结。局部“只改X”必须使用授权区域及区域外零漂移证据，不把整幅重生直接当作局部结果。多张可复用胸像表情交表情Skill。

明确进入动画制作且需要黑白红角色卡时，以批准通用角色卡为身份与版式源、`black-white-red-style-reference.jpg` 只控制画风，使用 `black-white-red-character-card / animation-card` 网页合同；提示库锁定基底不可改写，若当前分支适用纹理模块则逐字追加后把完整文本整体封入提交包。网页回执通过后仍须检查同一角色、同一版式、近灰度皮肤和小面积红色；未触发动画分支时不生产。

## 通用肖像与锁定回退

肖像须是角色卡派生的新渲染，不能把卡内头部放大替代。默认锁定版本 `portrait` 绑定两张图：批准同角色卡 `identity` → 通用肖像参考 `style_only`。当实际候选显示图2带入他人身份时，先记录失败证据，再消费同一肖像预算的下一次尝试，使用 `portrait-single-reference`；只绑定批准角色卡，风格段来自同一原文，不追加图2或自由改写。新版本没有悬空图2指令。

提交前用共享 `scripts/verify_locked_prompt.py` 导出，再以 `--verify <snapshot> --reference-manifest <manifest.json>` 验证；manifest包含 `prompt_id` 和有序 `references`，每项为 `path`、`role`、`sha256`。路径相对manifest目录解析，文件须存在且hash匹配。示意：`{"prompt_id":"portrait-single-reference","references":[{"path":"approved-card.png","role":"identity","sha256":"<actual SHA-256>"}]}`。实际工具调用逐字使用快照并遵从此相同参考数组；记录工具返回job，不能只锁文本而换图。

艺术验收比对具体脸型、五官距离、发际线、年龄、服装及原生画风；任何同类人替换立即失败。肖像原生截肩可以保留，背景比例及边缘规范在艺术通过后处理；不自动增加肩胸内容。只有表情目标确实不适配时进入共享合同的一次人工源适配交接。

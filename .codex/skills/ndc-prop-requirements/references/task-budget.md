# 按对话任务独立计算额度

2026-09-09 用户直接指令，立即适用。此规则优先于五阶段及其引用中旧的跨任务累计、未知历史按耗尽处理和重复索要确认的文字。

- 新对话任务自动享有完整新额度。唯一判断依据为真实对话任务 ID，与资产过去生成次数无关；同一资产、旧候选、失败件在其他对话中的次数都不扣入。无需用户再次声明独立生产或答复追加额度。
- 同一对话中的继续、恢复目标、模型等级切换、跨日、改名和阶段切换，仍累计该对话已经发生的调用。不得伪造任务 ID 或自行创建新对话来刷新额度。
- 已授权工作由执行者自行检索、核对、选择、修复并推进，不索要例行确认、历史次数核对或追加额度的答复。能力受阻时先完成独立工作；当前对话额度耗尽后保留候选及具体失败原因，继续独立项并报告，不建立等待用户答复的关卡。
- 每个对话内保留原上限：同一母版状态最多三批、每批两张；每个入景、菜单或独立派生作业最多三张，均含首次。已合格资产按来源和质量规则复用。平台账号用量不属于此工作流额度。
- 保留原 batch、稳定 job ID、完整追加日志和资产历史。按真实 `task_id + job_id` 分别计数，其他对话历史另列；不得把资产累计数当作当前对话已用数。
- 候选按对应必需产物去重计入制作覆盖，未复核、已检查未通过、有效 PASS 分列。交付就绪比例单独统计，候选不自动获得 PASS；真实依赖、技术/视觉检查和 PS 安全交棒继续执行。

## 共用脚本

使用第五阶段的 `scripts/workflow_state.py`：

```text
python -B workflow_state.py budget --batch <batch.json>
python -B workflow_state.py attempt --batch <batch.json> --job <job> --prompt <完整提示.txt> --reason <本次原因>
```

默认从 `CODEX_THREAD_ID` 读取当前真实对话 ID；环境没有此字段时，执行者从任务工具或本地任务记录取得后传 `--task-id`，不向用户询问。日志的 `number` 为历史序号，`task_number` 为当前对话次数。

旧 `legacy_attempts` 默认只追溯；仅当 `legacy_task_id` 明确属于当前对话且次数确切时才扣入。未知历史不能推定当前额度耗尽。已有未标归属的真实 attempt，由执行者查本地原任务证据，追加一次归属：

```text
python -B workflow_state.py bind-task --batch <batch.json> --task-id <真实原对话ID> --reason <本地记录路径及归属依据>
```

绑定不修改旧事件，也不将资产更早的 legacy 数字扣入；同值重复不会清零，改变既定归属会被拒绝。旧日志若混有多个来源对话，不能把全部调用强行归给一个任务，应保留原记录并按逐条来源先完成迁移。恢复同一对话须计入该对话已有真实调用。结果未知的在途提交先核实，不重复提交。

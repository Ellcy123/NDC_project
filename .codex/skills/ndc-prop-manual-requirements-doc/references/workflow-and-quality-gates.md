# 执行与质量门禁

## 建立工作包

1. 解析项目根并创建本次 `{WORK_ROOT}` 受管目录。
2. 复制 `assets/manual-requirements.template.json`，填章节和 revision。
3. 记录当前来源快照；同一命令内每个来源只计算一次 SHA-256。
4. 从当前范围生成 item、scene、excluded 三个全集，先对账再填人工任务。
5. 运行 `manual_requirements.py validate`；错误只修正输入 JSON 或来源事实，不为通过校验删减范围。
6. 运行 `summary` 生成审阅摘要，并将计数与准备写入 DOCX 的内容逐项对照。

## DOCX 生产

使用当前环境可用的 `documents` Skill。首次创建／编辑命令前按其要求运行一次操作标记；用工作区依赖提供的 Python／Node，不使用系统别名。DOCX 的标题、章节和表格以机器 JSON 为数据源，解释性段落不得改写 JSON 中的事实、状态或计数。

长文档优先按场景分组。人工任务总表与逐场景明细都要保留稳定 task ID，方便回流时定位；同一任务在两处出现时内容必须一致。

## 机器检查

- `validate` 返回 0，报告中 `errors=[]`；
- Item ID、场景 ID、source ID、task ID 唯一且引用闭合；
- `scope.item_ids` 恰好等于 items 集合；scene packages 不漏当前场景；
- 资产性质与取得路线计数分别相加到完整 Item 数；
- 每个人工动作都有任务，每个任务有输入、输出和验收；
- 所有 `unresolved` 都有未决问题，且不能被记为整项完成；
- DOCX 逐表计数与 JSON 相同，无占位符或隐式省略。

## 页面检查

用 `render_docx.py` 生成所有页面 PNG，并以原尺寸逐页检查：

- 标题和引言明确文档用途、范围与结论；
- 表头重复、边框完整、无截字、重叠、缺字或过小字体；
- 没有只剩一行的孤立尾页、意外空白页或因表格禁止分页造成的大空洞；
- 长路径和 SHA-256 可换行，但不能越界；
- 页码连续，最后一页包含有效内容。

任何 DOCX 内容或格式修改后重新渲染全部页面。结构解析、PDF 存在或 PNG 数量不能代替逐页视觉观察。

## 交付与续作

最终交付只含通过复核的 DOCX；JSON、验证报告、Markdown 与渲染页留在工作过程。交付说明报告完整范围、人工任务数、阻塞数、文档页数和当前非正式状态边界。

下次续作先比较来源哈希、活动范围哈希和 revision，只重算受影响 item／scene，并保留旧文档与旧 JSON 作为时间戳版本。不得覆盖历史文档后声称来源从未变化。

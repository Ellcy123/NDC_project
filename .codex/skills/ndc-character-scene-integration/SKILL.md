# NDC Character Scene Integration

Use approved scene art and approved character cards as the source of truth. Keep this workflow separate from character design and background generation.

## Mandatory stage-end visual self-check gate

Every art-production stage executed by this Skill must end with an actual visual self-check before its output may be accepted, passed to a later formal stage, packaged, or released. This includes reference/whitebox acceptance, generation, extraction, matte work, registration, compositing, shadow work, state assembly, normalization, derivation, and final packaging. Inspect the current whole image at `100%` and every applicable local region at nearest-neighbor `200%` or through complete original-pixel tiles. Compare against the current source authority and every applicable identity, performance, scale, contact, occlusion, UI, gaze, style, texture, edge, and preservation requirement.

Write one current `ndc-stage-visual-self-check/v1` JSON record per executed stage. It must bind the stage ID, reviewer/date, input and output paths plus SHA-256, the inspected `whole_100` and `local_200_or_tiles` views, every applicable criterion with an explicit finding and `PASS`/`FAIL`/`NOT_CHECKED`, the overall `visual_check_status`, and the responsible rework stage when blocked. Missing record, missing visual-detection item, stale output hash, missing required view, `FAIL`, or `NOT_CHECKED` is `STAGE_VISUAL_SELF_CHECK_GATE: BLOCKED`: do not mark the stage passed, use its output downstream, or call it formal. Technical validators, dimensions, hashes, Alpha/mask reports, or absence of a detected error cannot write visual `PASS`.

After a block, return to the responsible stage, perform the missing inspection and required repair/regeneration, then repeat the visual self-check on the new current output. Release only after the current hash has a passing record. For every file-producing stage, run `python scripts/art_pipeline/ndc_art.py tool stage --record <visual-review.json> --artifact <current-output>`; a nonzero result is a hard stop. The existing per-stage retry ceiling still applies, and exhausting it leaves a candidate rather than weakening this gate.

## Required workflow

Read [full-workflow.md](references/full-workflow.md) and [directing-and-timeline.md](references/directing-and-timeline.md) before starting production or auditing a failed run. Their stage order and stop conditions are mandatory.

1. Classify the runtime branch as `exploration-click-pair` or `pure-narrative`; never infer a timeless full cast from a single still. Read the dialogue, engine tables, scene configuration, approved character profiles/cards, and existing NPC assets. Missing branch, timing, identity, canonical height, or state means skip the scene.
2. For pure narrative, extract the engineering entry/exit chain and author incremental directing snapshots. For exploration, author idle and active interaction meanings. Summarize each snapshot as objective, conflict, emotion, subtext, action focus, and one silent-frame statement.
3. Build a scene-affordance map from the fixed background, depth image, and model image. Mark where actors can walk, stand, sit, lie, lean, reach, pass behind/in front of objects, and enter/exit. A standing/sitting zone polygon represents the support anchor region, not a vertical full-body rectangle. Author support contact polylines and support occupancy independently from the character joints. An occupied chair/bed/table cannot be used until its loose objects have a specific retain/remove/relocate plan. Fixed structural furniture never enters a scalable/generated actor component: use one bounded source-repair patch at the loose object's old location, one relocated-object layer at its new location, and exact 1:1 source occluders for the unchanged furniture.
   For every narrative entrance, record the portal and a clear entry path that does not intersect frozen actors. A visibly closed door cannot be used as proof of an entrance unless the current snapshot includes the door-opening transition; otherwise stage the actor after entry in a physically reachable zone and do not label the pose `entering`.
4. For each snapshot, choose one actual dialogue-UI side from the left/right composition references after the cast blocking is understood: place the UI on the side with the lower narrative and visibility cost, record that single `uiSide`, and validate only that applicable mask. Do not require the same snapshot to pass both mutually exclusive UI sides. The opposite-two-thirds shortcut is not a final gate. Faces and declared critical hands/props must remain readable under the selected snapshot UI. If a UI reference is extended to a wider panorama, preserve genuine transparent padding and visually inspect the composited preview; transparent RGB residue is not UI obstruction, and opaque blank padding invalidates the gate.
5. Resolve each actor's performance contract before choosing a pose: silent-frame verb, beat energy, ongoing occupation, performance family, exact action, emotion, body line, weight distribution, facial expression, motivated purpose for both hands, named support, social territory, facing, gaze, costume state, ten-second hold validity, props, depth honesty, and occluders. Choose among ongoing occupation, supported hold, transition, or confrontational action only when the current beat authorizes that family. Reject generic upright, symmetrical, camera-facing stage poses and unmotivated wide stances/open-hand reaching, especially in still or low-energy beats.
6. For narrative scenes, block the earliest cast first and freeze each uninterrupted actor's pose, transform, placement, and affordance zone. Add later entrants without changing existing actors; an actor cannot look or react toward a future entrant. Render and silently read the incremental timeline board before scale work.
7. Read [placement-decision-chain.md](references/placement-decision-chain.md). Build one placement contract per actor presence and one scene staging contract per simultaneous-cast snapshot. Scale calibration must include at least one medium/high-confidence anchor local to the actor plane and one independent anchor at a materially different depth. Before cast-relative comparison, run `validate-scene-absolute-scale` with at least three independent fixed-scene objects spanning horizontal and vertical dimensions plus actor-local and cross-depth bands. It recomputes each measurement line, projects it to a named actor plane, and returns one robust global correction factor. If anchors disagree, repair the depth geometry; if they agree that the entire cast is too large or small, rebuild every whitebox around its support contacts rather than resizing final cutouts. Then run `validate-cast-scale` v2 with `headScalePriority: true`: first compare each whitebox anatomical head height and every pairwise head-height ratio against the approved character-card head/full-body reference after shared depth projection; then use canonical height and support-point depth to verify standing-equivalent height and every pairwise body-height ratio. A cast-relative PASS can never override failed fixed-scene absolute scale, and a full-body PASS can never override a failed head ratio. The 170cm proxy is a technical ruler only and never a composition, identity, or generation reference.
8. Lock a full pose, not only a foot point. Every standing, seated, or lying contract must contain the anatomical head box plus neck, shoulders, elbows, hands, hips, knees, feet, facing, gaze, hand actions, props, support, and action outer box. Sitting and lying change joint angles and outer-box shape, not body scale. A seated contract additionally records pelvis-to-seat support, feet-to-floor support, primary support foot, foot stagger, stance-to-shoulder ratio, torso facing, and the orientation rationale; foot placement influences the hip/knee/torso chain but never replaces explicit facing and gaze direction.
9. Record exact pose and placement coordinates in the structured contract, but do not render or use a stick skeleton, joint figure, or programmatic geometry-block character. Review the combined cast through the character-preview 3D anatomical mannequin whitebox head-first: at gameplay size, a nearer adult head must project visibly larger than a farther comparable adult head unless an approved identity-scale reference proves otherwise. Then review full-body height, position, contacts, action envelope, performance readability, actual-UI safety, and proposed occlusion relations at full-frame and local-tile scale.
10. Generate and review an empty-scene depth image independently, preserving the fixed camera and scene topology. Then create a character-preview 3D mannequin whitebox from the locked blocking: the scene stays white/light gray and the original camera/topology remains recognizable, while every visible actor is represented by a realistic 3D anatomical mannequin at the authored pose, support, depth, scale, facing, action, and overlap. Assign every simultaneous actor a stable, clearly distinct, medium-saturation matte material color that contrasts with the white scene and with every other actor; preserve that actor-color mapping through isolated guides and local handoffs. Color is an identification/segmentation aid only and never a costume, identity, depth, or narrative code. The depth image and character-preview 3D whitebox are a required paired reference.
11. Produce one isolated 3D mannequin reference for every actor presence and one combined-cast 3D mannequin whitebox for every simultaneous-cast snapshot. Do not combine actors who never coexist. Reapply scene occluders in declared order. Record the per-actor matte color in the placement/staging contract and keep colors separated enough for deterministic local segmentation without eating light anatomical surfaces. Never produce or use a red joint skeleton, circles-and-lines figure, programmatic block mannequin, generic marker, or outer rectangle as a character-placement image. The colored 3D mannequin must visibly express human head scale, shoulder width, torso/pelvis volume, limb thickness, joint bends, feet/support, and pose silhouette. Inspect it against the depth image, near and far furniture, canonical heights, pairwise head sizes, and the intended performance before generation. The combined cast establishes mutual blocking, but it is not sufficient evidence for an actor whose body is hidden by another mannequin or furniture: that actor's isolated reference must expose the complete body and support response at the identical transform. Every matte/preview board must be rendered from the same actor source and alpha artifact used downstream; a preview assembled from a different combined frame is invalid even if it looks plausible.
12. Run `validate-support-contact` for every placement before the Codex pre-generation gate. It must calculate every named anatomical contact against the scene-authored support line, emit a report and overlay preview, and reject both floating and sinking beyond tolerance. For a lying pose, line contacts alone are insufficient: the support surface must additionally author the full bed/support polygon plus separate head/pillow and foot-end polygons; the validator must reject a head outside the head region, either foot outside the foot-end region, any anatomical point or body-axis endpoint outside the support polygon, or a body axis whose endpoints do not correspond to head and feet. `supportContactConformance` cannot be manually asserted. The 3D whitebox must visibly prove the complete anatomy of every actor even when final bedding or furniture will cover it. For a covered lying actor, render the blanket/support as transparent, ghosted, cutaway, or an equivalent 3D inspection layer so head, shoulders, torso, pelvis, knees, both legs, and both feet remain inspectable through the full head-to-foot support length; a head-and-upper-torso mannequin plus an inferred blanket mound is incomplete and fails. Contact geometry is still incomplete without a visual `environmentResponse` check: every soft, movable, compressible, supported, or mutually touching scene element must show the physically expected deformation, displacement, load, wrap, indentation, overlap, or cast/contact shadow. A lying actor therefore requires visually continuous mattress compression and bedding rise/wrap corresponding to the complete hidden body, not merely a head placed on a pillow. Run `validate-component-policy` for every planned actor/prop/support assembly; it rejects fixed structural objects in generated/scalable layers and requires paired source/destination regions for every loose-object relocation. Then gate timeline, affordance, actual UI, depth, isolated whiteboxes, snapshot combined whiteboxes, absolute scene scale, cast-relative scale, support reports, component-policy reports, and pairwise occlusion table. Review whole frames and complete local tiles, record artifact hashes and pose IDs, and mark `READY_FOR_CHARACTER_GENERATION` only when semantic and structural checks pass.
    Then create `ndc-scene-integration-production-ledger/v2` and run `scripts/production_gate.py`. Do not generate while the evidence ledger fails. A flat production manifest, a script-generated filename, an asset count, or a hard-coded report string cannot substitute for this ledger.
13. After the combined 3D whitebox passes, isolate each actor's anatomical 3D mannequin from that accepted image as a process-only RGBA guide, preserving the complete silhouette, prop envelope, pose, and pixel registration. Composite that guide at its locked coordinates onto the untouched original scene; never use the globally neutralized 3D room as the character-generation Image 1. Visually review the complete mannequin silhouette, support contact, scale, scene occlusion, and absence of extraction fringe on the original-color scene. Then prepare a deterministic local-generation handoff centered on this approved original-scene-plus-3D-mannequin overlay. Choose a generation aspect ratio supported by the active image model from the full action envelope and required support/context, then expand a 1:1 original-pixel scene crop to that ratio without resizing it. Record both requested and returned canvas ratios; any unsupported-ratio substitution or returned-ratio mismatch stops registration before mapping, and the output must be regenerated at a supported ratio rather than stretched or cropped into compliance. Image 1 is this local crop containing the isolated 3D mannequin over the original scene, Image 2 is the untouched full scene for camera/light/color context, and Image 3 is the approved character card. The prompt must name these roles and require replacement of only the mannequin. The approved 3D mannequin overlay is the generation authority only after the independent absolute-scene and cast-relative scale gates pass; nearby objects remain visual regression checks and must send a contradictory result back to scale calibration. Any local handoff derived from a stick figure, joint diagram, programmatic geometry block, or globally neutralized room is invalid for new production.
14. The first generation pass must be an in-place contextual local replacement, not an isolated transparent-character request. Compare identity/style against the card and pose/contact/scale against the whitebox before any extraction. After those checks pass, run a separate semantic/background-removal pass. A hand-authored polygon may define the authorized change/protection region, but it must never become the final actor alpha. If a light neutral checker is baked into RGB, use `scripts/conservative_matte.py`; if a saturated green removal pass is explicitly used, use `scripts/chroma_green_matte.py`. In both cases black, white, and dark scene-tone previews are mandatory and must prove complete hair, fingers, shoes/heels, held props, and clean RGB edge color before composition. A correct alpha cannot excuse contaminated edge color, and no inward erosion may conceal either failure. For a soft-environment interaction such as a covered patient, cushion indentation, or displaced blanket, do not extract and scale the bed/chair/furniture with the actor. Build a minimum interaction patch containing only the actor plus the physically responding soft material, preserve fixed rails/frame/support outside it at exact source pixels, and visually inspect the patch by itself before adding any standing cutouts. After alpha coverage passes, one documented uniform scale plus translation may register the actor and authorized loose props to the approved whitebox/Photoshop coordinates only within conformance tolerance; fixed furniture is excluded from this transform. Anisotropic scaling, warping, joint correction, or registration used to rescue a wrong performance is forbidden. If the generated actor misses a correct whitebox, regenerate; if it matches the whitebox but still reads at the wrong scale in scene, return to depth/scale/whitebox. Reapply exact source-scene occluder masks, including holes, and composite each snapshot on untouched source pixels in declared layer order. Add contact/cast shadows only after their support and light direction are visually verified, then inspect foot contact again. At final size, annotate eye center, face-direction point, and named target point and run `validate-gaze-conformance`; a text contract cannot pass a visibly wrong gaze.
    Visual inspection is mandatory at every image-producing or image-transforming stage. Run `scripts/visual_review_gate.py` for the exact-pose whitebox, contextual local result, matte extraction, pre-composite registration preview, and final full composite. Codex must open the resulting board and inspect the whole image plus every actor/action/overlap tile before authoring the review findings. Geometry, hashes, dimensions, alpha boxes, scripted scores, and file checks may locate risks but can never declare visual scale, placement, contact, performance, edge quality, or integration correct. A failed visual stage stops the next stage.
    The accepted contextual local image retains a reproducible crop-to-scene transform: map its complete generated canvas back to the original `cropBBox` before judging the extracted actor. Before final composition, render a registration preview on the untouched full scene and compare it side by side with the accepted contextual local image, near furniture, far furniture, every visible head, and the simultaneous cast. Do not discard that transform and then normalize the alpha to a hand-authored height. If the accepted contextual result reads correctly but contradicts the old whitebox, mark the whitebox/scale gate failed, revise and revalidate those contracts, and only then continue; do not silently choose either data source.
    <!-- NDC_TEXTURE_COHERENCE_MODULE:BEGIN -->
    Before extraction, compare the contextual result with both the approved character card and untouched full scene under separate `STYLE_LOCK_GATE` and `TEXTURE_COHERENCE_GATE` reviews. Preserve the card's identity, palette/value compression, ink hierarchy, grouped shadows, brush language, and material treatment, while preserving the scene's existing texture scale and density outside the minimum interaction component. Reject invented garment micro-detail, repeated marks, random speckle, fragmented strokes, new seams, uniformly sharpened edges, or a character whose detail frequency no longer fits the scene depth. The original full scene remains pixel authority outside the authorized component.
    <!-- NDC_TEXTURE_COHERENCE_MODULE:END -->
15. For exploration states, read [state-variant-assembly.md](references/state-variant-assembly.md) and run the dedicated pair validator. For shadows, read [shadow-construction.md](references/shadow-construction.md). Package by scene basename and verify with [delivery-contract.md](references/delivery-contract.md). Technical reconstruction cannot pass missing semantic/directing approval, wrong placement, or wrong occlusion.
    Before final packaging, rerun the production ledger with `stage: post-generation`. File-only checks may report `TECHNICAL_FILE_PASS`; they may never emit an unqualified `PASS`, `hardGatePass`, or formal-delivery status.

At any decision point, make up to six valid attempts on the same branch without interrupting the user. Recheck after every attempt and change the failed variable instead of repeating blindly. If all six fail, select the closest result by fewest/severest failed gates, label it `best-available candidate`, keep it under `工作过程文件`, record every unresolved item, and continue the batch. Present all formal results and candidates together for one final user review. A candidate may never enter `最终交付` or be described as PASS.

## Completion gate

Do not call a result formal until the runtime branch and cast timeline are resolved, every frame passes the silent-frame statement, affordance and actual-UI checks pass, the Codex-reviewed exact-pose snapshot whiteboxes and occlusion graphs exist, the final cast passes full-frame and complete local-tile comparison against timeline/whitebox/depth, both texture/style gates and their validator pass, and the user can reconstruct each state at 100% scale from the delivered RGBA asset and Photoshop top-left `(X,Y)` without changing pixels outside the authorized alpha region. Do not interrupt the user during normal retries; collect the completed formal and candidate results for one final batch approval.

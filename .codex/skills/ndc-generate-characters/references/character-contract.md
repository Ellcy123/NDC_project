# 角色阶段合同

用于原入口、身份母版与资产派生之间的实际交接。任务授权持续有效；清单由执行者核实后推进。

## 身份、提示与适用范围

- 用户明确选图冻结该资产的艺术搜索；不因推断出的笑容、性格或可后补道具重开身份设计。用户原始提示仍有效时不得自由改写。
- 将来源分别标为 `identity`、`style_only`、`landed_peer`、`rejected_example`；拒收图不转批准身份源，风格参考不提供他人的脸。角色卡是已有角色状态和肖像的身份依据；MJ原始头部不是正式肖像。
- 把表情、心情及可移动道具标为当前明确要求的 `HARD_NOW`、可后补的 `DEFER_TO_IMAGE2` 或 `DOWNSTREAM_STATE_ONLY`。不把抽象性格强加到中性角色卡或肖像上。
- “只改X”先冻结源和授权区域，候选只取该区域回贴；区域外还原原像素并核验。没有可信遮罩和区域外保持证据，不能声称只改X。

## 最小交接内容

沿用同一任务ID和持久记录，包含角色ID／别名、当前需求版本、资产类型／状态／视图、`source_authority`文件与hash及批准依据、同源面部锚点、不可变身份／服装／配色、参考角色、提示版本、输出／父资产hash、已做审核的范围与状态、未解决缺项、剩余预算和下一责任阶段。只传递实际存在且有依据的项目；历史缺失记录不补造。

身份生产终点是通过的通用风格身份母版；派生阶段不得把其失败解释为重新设计许可。一个派生失败只使真实依赖它的下游失效。用户否定精确版本后，旧PASS保留为历史但不能继续授权该版本及其后代；已通过的独立资产保留。

## 身份阶段状态

重要新角色继续保留原有顺序：`BRIEF_LOCKED → MJ_CANDIDATE → USER_SELECTED → [REPAIR_CANDIDATE] → IDENTITY_LOCKED → GENERAL_STYLE_CANDIDATE → GENERAL_STYLE_LOCKED`。既有用户选图证据直接继承，需求清单确认不能替代艺术选图；`USER_SELECTED`也不自动通过技术或视觉门禁。预算耗尽的MJ分支只能走 `FALLBACK_SELECTED → REPAIR_CANDIDATE → IDENTITY_LOCKED`，fallback本身不能跳成身份锁。次要角色记录 `BRIEF_LOCKED → IMAGE2_IDENTITY_CANDIDATE → GENERAL_STYLE_LOCKED`；派生记录明确父源、当前候选、艺术通过、技术通过和正式状态，不凭文件存在跳转。

每次艺术调用前记录当前状态、来源权威、允许的下一状态、提示锁状态、上游阻断与预算。必要提示锁未通过或存在上游阻断时不启动正式后代。用户另有明确探索候选授权可继续 `CANDIDATE_ONLY` 链，保留原始失败和全部阻断；这些输出不能成为正式批准身份源。浏览器、下载或检查失败只允许恢复原job或停止该执行分支，不自动切换身份生产路线。

## 人工肖像适配

通用肖像允许原生截肩，本流程不自动补肩。若表情目标需要更完整肩胸或其他原图缺失区域：

1. 保留当前已批准肖像及可用范围，输出 `WAITING_FOR_MANUAL_PORTRAIT_COMPLETION`；记录目标裁切／规格、缺失区域、冻结身份和原始hash，向人工发出一次具体交接，不把原通用肖像改判为失败。
2. 人工在受管工作副本完成适配。Codex不得以自动扩图或新表情生成替代人工这一步；等待影响该角色的表情分支，其他独立资产可继续。
3. 收到人工回传及完成说明后，接收该版本，核对来源对应、真实身份／服装／画风、目标裁切完整性和技术规格，记录当前路径／hash、人工完成依据及适用范围。回传已说明完成时不再重复询问确认；原肖像及交接前哈希保持不变。
4. 合格源进入表情 Skill；若仍不适配，返回这同一人工交接的具体未满足项，不重启角色设计或另开自动补全循环。

## 视觉证据与技术整备

每个实际艺术阶段须有真实整图100%和适用局部最近邻200%／原像素覆盖检查。身份、结构、风格、纹理、内容失败不能由尺寸或hash代替PASS。按 [持久生产记录](production-record.md) 引用同源、同需求、同范围且未失效的证据；阶段名改变不要求重复观看完全相同的像素。复制／包装检查映射、hash与来源，裁切复核新规格可读性，Alpha操作复核完整边缘；新增或受影响风险仍需真实查看。

新图艺术通过后冻结，再做必须的透明化、等比缩放、位置与边缘整备；技术问题不反向改写锁定提示。PS采用当前允许的原生MCP路径，本机同一时刻仅由一个任务操作：同任务当前图完成保存、技术及真实视觉检查并核对当前hash；未审完不推进下一张，PASS才推进相应依赖，FAIL在缺陷明确且原预算耗尽或用户指示封存后，保留证据并仅继续独立资产；安全保存恢复文件和固定审阅快照后可挂起释放给其他独立任务，当前未通过状态及依赖保持。模块DAG不授权同时操作PS文档，也不因释放获得新预算。

形式放行沿用专门阶段、texture与delivery验证器及真实视觉证据，不把技术PASS当视觉批准，也不将候选称作用户已批准。正式文件与过程证据遵循当前项目目录规则。

# 角色预算与实际依赖

生产前与续作时读取，计数写入 [持久生产记录](production-record.md)。预算按真实对话任务ID区分；新对话自动拥有各分支完整新额度，旧资产历史不扣减，不索要答复。同一对话内改文件名、切换Skill或返修不重置该对话次数。详见[对话额度](task-budget.md)。

## 分支预算

| 生产对象 | 有效生成预算（含首次） | 到顶动作 |
|---|---|---|
| 重要角色MJ全身候选 | 既有123：最多3组，每组INITIAL四图→Subtle四图→Strong四图，共最多9批36张 | 无PASS只保留FALLBACK_SELECTED，带缺陷转有限修复候选，不能锁身份 |
| 确实需要的MJ独立头部候选 | 单独遵循同一123上限 | 同上，不因头部失败自动重开全身预算 |
| 身份精修、次要角色Image 2母版、MJ→通用风格转绘 | 每逻辑阶段最多3次；已有更小明确预算从严 | 停该对象，保留候选与缺陷，继续无依赖对象 |
| 普通整卡、通用肖像、单次状态变体、各独立全身／新角度头部／鞋／细节模块 | 每逻辑资产最多3次 | 不选最接近者冒充PASS |
| 同角度头部锚点的纯清晰度补充 | 既有1次补充；直接原像素裁取不消费生图次数 | 仍不足保留缺口，不反复以清晰度名义重画 |
| 肖像单参考回退、局部艺术修复 | 消费其原始逻辑资产剩余艺术预算，不另赠3次 | 预算耗尽即停止该对象 |
| 同一技术问题 | 保留既有连续2次失败停止；跨工具和阶段累计，不以新文件名重置 | 保留艺术通过源与失败技术版本，报告差异 |

所有初始尝试都计数。有效候选内容失败计为艺术尝试；已提交但结果未确认时先查原job，不能重发并称工具错误。明确未生成结果的文件、权限或工具错误另记 `tool_error`，不消费艺术候选数；同一不可恢复原因连续2次失败停止该工具分支。结果未知的提交保留待对账计数，重连后关联原job，杜绝双重提交。

123是上限和条件路线：任一批有PASS即停止该候选搜索，不为了凑满36图继续生成。该上限不被新默认3次替换；后续修复阶段也不能借fallback无限循环。

## 模块触发与视角字段

- `explicit_4k_requested=true` 或有用户明确“独立模块生成／拼版”的原文，才启用模块化；普通“高清／正式”不触发。
- 4K终稿固定3840×2160。只有分模块请求而未要求4K时记录 `explicit_modular_requested=true`，采用任务约定尺寸；完整卡拼版未另定时使用既有2K 1920×1080。只补单模块时按该模块规格及已批准同组源处理，不给单背面套横向整卡画布，也不把分模块等同4K。
- `fullbody_left` 保留兼容ID，指鼻尖／面向画面左侧的严格全身侧视（`screen_facing=LEFT`）。`head_right` 保留兼容ID，指展示角色解剖右脸的严格头部侧视，明确记录 `visible_character_side=RIGHT` 和实际 `screen_facing`，不能把“画面向左”与“角色右脸”当同一字段。
- 先核实每个源实际可见面再建立映射。若全身侧视头部与头部目标可见面不一致，不得直接裁用或镜像；有已批准同角度锚点就复用，否则从批准身份源生成所需新角度并记为艺术派生，不能写成同源裁片的纯清晰度补充。左右非对称配饰和头发结构保持人物本体关系。

## 模块依赖图

`approved_identity → fullbody_front → {fullbody_left, fullbody_back, shoe, approved_details}`；`fullbody_front → head_front`，`fullbody_back → head_back`；`approved_identity + fullbody_front + 可用同角度锚点 → head_right`。头部直接裁取须匹配相同实际视角；无同角度锚点的head_right走上段新角度分支。

正面及身份是共同基础；其失效阻断所有真正后代。左侧失败只阻断依赖该侧视的对象，不阻断已可执行的背面、正面头部或独立细节。全部要求模块通过后才拼版；布局或技术问题只重组受影响输出，不重画通过模块。同任务PS当前图须完整保存、完成真实自检并核对hash；未审完不推进下一张，PASS才推进相应依赖，FAIL在缺陷明确且原预算耗尽或用户指示封存后，保留证据并仅继续独立资产；可恢复保存及固定审阅快照后的跨任务交棒须保存可恢复文件并确认无在途或未知命令，不是另开模块预算。独立模块可并行准备，但不能同时操作PS。

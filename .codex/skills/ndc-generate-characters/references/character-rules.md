## 1. 证据状态

- 用户明确规则可以作为强规则执行。
- 往期文件对比所得结论属于案例归纳，应在输出新判断时注明证据状态。
- 当前角色规则只适用于 NDC 角色分支，不自动推广到场景分支或其他独立美术风格。

## 2. 强制规则

1. 用户亲自提供的提示词与用户明确选定的图片拥有最高艺术优先级。提示词在用户明确声明停用或替换前持续生效；不得为了满足模型从角色设定中推断出的表情、气质或道具而擅自改写。用户明确选图后，该资产艺术候选立即冻结并结束艺术搜索，只可继续非生成式规格处理、打包和留证，除非用户明确要求艺术修改。
2. 角色设定中的抽象性格或外观气质不得自动变成当前阶段的表情硬门槛。角色卡与肖像若使用的锁定提示词要求“面无表情”或“中性”，则中性结果为正确结果；即使 MJ 概念图带笑，下游也应按锁定提示词回归中性。缺少“和善微笑”、威胁感或其他推断表情不得作为角色卡、肖像或 MJ 候选的拒收理由。
3. 角色设定中的便携道具、剧情持物和可后补小物件默认不作为 MJ 候选硬门槛。缺失时记录为 `DEFER_TO_IMAGE2`，继续身份与造型流程；只有用户提示词或明确指令将其标为当前阶段不可延后的身份核心时，才可作为 `HARD_NOW`。不得仅因道具缺失回头重做 MJ 概念设计。
4. Midjourney 是重要新角色的主生成环节；不重要的新角色可以跳过 MJ，直接使用 ChatGPT Image 2。
5. MJ 使用当前默认模型，不添加 `--v`、`--V 8.1` 或任何模型版本参数。
6. MJ 全身与可选头部都必须同时启用两张核心风格参考图的 Use style。
7. MJ 网站固定进入 `https://alpha.midjourney.com/imagine`，不得再依赖左上角图标识别 Alpha 版本，也不得改用无 `alpha` 前缀的网站。
8. 两张核心风格参考图已保存在 MJ 账号中。点击 Imagine 页面右上角的 `Images`，在下方弹出的已保存图片中选择对应两张，并分别设为 `Use style`；正常流程不重新上传本地副本。
9. 两张 MJ 参考图共同控制风格，不固定角色身份和服装内容。
10. 通用风格角色卡是标准角色资产。通用风格肖像只为重要、复用、界面展示或明确需要近景的角色生成；不重要角色默认不生成肖像。
11. 默认只输出提示词、参数、参考顺序与验收规则，不自动执行图片生成。
12. 不重要的新角色直接使用 Image 2 时，使用 `general-fullbody-style-reference.png` 作为风格参考，并复用通用风格全身转绘与角色卡阶段的同一套角色风格提示词。
13. 既有角色的其他状态图必须以现有已批准的通用风格角色卡为基础参考，再按状态需求生成；不得在角色卡存在时仅凭文本重新创造角色身份。
14. MJ 全身候选中，背在身后或被身体遮挡的手属于明确姿态瑕疵；条件接近时优先选择双臂自然下垂、双手完整可见的候选。只有当该候选在体型、头身比、头部或角色符合度上明显更优秀时才可保留，并必须在进入角色卡阶段前使用 Image 2 修正。
15. 角色卡三视图中的每一个全身视角都必须双臂自然下垂、双手空置，不得沿用背手或插兜姿态，也不得手持、夹带、悬挂、接触或以任何方式携带道具（包括文件夹、信封、记录盒、钥匙圈等）。正面与背面视角必须能看到两只下垂的空手；严格侧视时远侧手允许因正投影自然重叠，但手臂本身仍须下垂，不能藏到背后。经批准的道具只能作为右侧细节区中的孤立物件展示，不得与三视图人物身体或手部相连。
16. 黑白红角色卡必须首先保持黑、白、红三色特征，不能恢复成通用风格的正常肤色。皮肤只允许在近灰度基础上带极轻微暖灰褐/暗赭倾向，饱和度必须显著低于通用角色卡；既不能大片漂成纯白，也不能明显呈现棕色、橙色或自然肤色。
17. 黑白红中的红色只作小面积信号色。除非原角色已批准设计明确要求，否则禁止大红底、大红色带、红色边框、大面积红色地面块或服装红色面板。
18. 肖像风格参考只控制画法。若参考人物把角色的性别、年龄、相貌、发型或服装身份带偏，立即拒收，并改用通用角色卡单图锁定身份，以文字复现肖像画风。
19. 黑白红角色卡暂时退出标准角色工作流。只有角色明确进入动画制作时才单独触发；现有黑白红提示词、低饱和皮肤和小面积红色规则继续保留。
20. 生成阶段与技术交付阶段分开。原生艺术候选可在身份与画风检查后再处理比例和尺寸，不得因原生输出未达到最终比例而改写锁定提示词；最终文件仍须读取实际像素，通用角色卡与黑白红卡为 16:9，通用肖像为 4:5。最终不得非等比例拉伸。
21. 出库前必须分别对照项目三个自检库。自检以整组库的共同特征为准，不得只挑一张相似样本。
22. MJ 头部质量必须同时满足“结构正确”和“身份特征可读”。两眼、眉眼间距、鼻梁与鼻尖、嘴部/胡须、颧颌轮廓和发际线需要能在同一张身份锁定图中比较；大面积阴影遮没一只眼或一组关键特征时不能判定通过。
23. 通用风格转绘不得只保留年龄、发型、胡须和服装等类别特征后重新设计五官。必须逐项继承 MJ 身份锁定图中的人脸几何；角色卡右侧必须包含正面、严格右侧面和背面三个头部特写，三视图必须等比例对齐；细节区不得用无识别价值的衣料切片填充，批准道具若展示必须为与人物分离的孤立物件。
24. 通用角色卡默认使用 `prompt-library.md` 中锁定的整卡提示词一次生成，以身份和画风稳定为优先。只有用户明确要求 `4K` 时才采用模块化生产：分别生成全身正面、严格左侧面、背面，头部正面、严格右侧面、背面，角色穿着批准鞋型的双脚/小腿特写，以及零至三张经批准的装饰/道具/构造特写。每张模块必须单独保存、单独验收，再以确定性脚本拼到精确 16:9 纯白画布；最终拼版不得再次调用图像模型重绘已批准模块。
25. 模块化角色卡的所有视角必须从同一批准身份与设计源派生。全身视角同时锁定脸、体型、头身比、服装层级、配色、徽章/固定配饰位置与鞋型；头部视角同时锁定脸型、眉眼间距、鼻形、嘴部、颧颌轮廓、耳形和发际线。任一模块只达到“同类人物”而非同一角色时，单独返工该模块，不得靠最终拼版掩盖。
26. `4K` 仅由用户明确提出时触发，最终文件必须为 3840×2160 像素。不得把低清整卡直接插值放大冒充 4K；应让各独立模块在生成时获得足够像素，并在拼版时优先缩小或原尺寸放置。用户未明确要求 4K 时不得自动进入模块化路线；若另有明确 2K 或精确尺寸要求，在艺术候选通过后按技术整备处理。纯白画布、无边框、无水印，除非用户明确要求文字标注。
27. 三张全身模块拼版时必须先裁去纯白外边距，再统一主体总高度，使头顶和脚跟精确共线；随后人工复核肩、腰、膝和服装构造线。禁止按各图原始像素尺寸分别靠底摆放，禁止在三视图上方留下没有设计用途的大块空白。若内部基准线在统一总高度后仍明显不一致，必须返工相应视角模块，不能靠最终画布掩盖。
28. 通用角色卡的服装体积必须由少量明确的硬转折、硬边平面色块和大面积安静暗部构成。肩、肘、袖口、腰、膝与衣摆等受力点可以出现有方向的折面；禁止用连续柔滑渐变、圆融融化式衣褶、空气刷过渡、密集装饰性碎褶或亮面 3D 高光代替结构。
29. 通用角色卡的轮廓线与内部衣褶线必须具有可见的粗细变化和手绘节奏：主要受力轮廓与深层遮挡处加重，服装边界使用中等且收尖的线，内部折线更细并选择性中断。线条需要有鼓胀、收尖、断续和明确收笔；均匀细线、机械顺滑矢量线、每处同等加粗均判风格失败。
30. 用户提供经确认或主动调整过的色相版本时，该版本成为后续局部风格返工的颜色权威。除非用户同时要求重新配色，只允许修正衣褶折面、墨线和局部明暗边缘，不得改变现有色相、肤色倾向、服装配色、角色身份、造型或已通过模块。
31. 正式角色卡版式固定为：全身正面、严格左侧面、背面占画面左侧三分之二；头部正面、严格右侧面、背面占右侧区域的上半部；穿鞋结构与其他批准特写占右侧余下区域。最终画布为纯白、无分格边框。只有坐标落入对应区域但人物实际过小、比例不齐或留下大块无用途空白时，仍判失败。
32. Codex 执行的正式生成、拼版、自检和交付必须读取 `execution-gates.md`，先建立身份、风格、横向落地样本和否定样本的分角色清单，再逐阶段填写回执。门禁只允许 `PASS`、`FAIL`、`NOT_CHECKED`；任何 `FAIL` 或 `NOT_CHECKED` 都阻断正式拼版、正式技术整备和正式交付。用户明确要求完整流程、探索或候选集时，允许继续生成下游候选，但每个下游文件必须标为 `CANDIDATE_ONLY`、记录上游阻断项，且不得作为批准身份源或正式资产。
33. 正式肖像必须先在肖像分支使用锁定原提示词重新渲染；角色卡或全身图的裁切、抠图、插值放大不能替代该艺术生成。新渲染肖像通过身份与画风后，允许对该肖像本身做抠图、等比例缩放、目标画布定位和非生成式边缘清理，且这些技术操作不得改变脸、发型、服装、配色、光影和内部笔触。原生构图中的缺肩或截肩可直接保留，不增加补肩、扩图或局部生成环节。
34. 背景透明化只能在原生艺术候选已经确定并冻结后进行。锁定肖像提示词中的暖象牙纸张底用于稳定生成画风，不表示最终透明交付可以省略，也不得将“透明背景”提前追加到锁定提示词。透明肖像必须对完整人物轮廓分别进行黑底、白底和高饱和红底检查；只检查透明角落不能证明合格。
35. 每个通过结论必须绑定可复核证据：实际尺寸、来源与缩放记录、必要包围框、完整参考路径及其用途、整图检查状态和原像素局部覆盖状态。脚本运行成功、哈希相同或机械规格通过不能单独构成正式通过。
36. 肖像与普通角色卡的主提示词为不可改写的生产资产。调用生成工具时必须逐字提交对应代码块，不得摘要、翻译、扩写、追加透明、尺寸、人物占比、补全、负面词或角色专属描述；角色身份和设定由参考图提供。提交前保存提示词快照并核对与源文本一致。
37. 角色资产先通过身份、结构和画风，再进入技术整备。抠图、等比例缩放、画布定位和边缘清理只解决交付规格；局部扩图/补全仅用于角色卡、全身图等非肖像资产的必需结构缺边，肖像缺肩不进入该环节。技术问题不得通过改写生成提示词或重画整个人物解决。
38. 技术整备后的新资产人物包围框和人物占比不得超过对应历史资产最大值。若提出例外，必须同时记录头部占比与画面位置，并证明轮廓上限变化由头部构图规律造成，再提交用户确认；不得由模型自行放宽上限。

## 3. 头部质量闸门

```text
选定全身候选
→ 两眼、鼻部、嘴部/胡须、颌面轮廓和发际线是否同时清晰，结构合理且具有可继承的独特身份？
  ├─ 是：跳过单独头部，直接精修全身素材
  └─ 否：用同一双参考图额外生成 9:16 头部素材，或在身份锁定前局部修复/重新照明面部
```

单独头部与全身脸不要求一致。验收单独头部时检查：

- 年龄、性别、族裔（若设定有）、气质、时代、职业是否符合描述；
- 五官与头骨结构是否清楚、无明显畸变；
- 发型轮廓是否完整且可用；
- 戏剧性阴影是否只塑造体积而没有吞没眼睛、鼻部、嘴部/胡须或颌面轮廓；
- 是否适合作为替换、重绘或局部修复依据。

MJ 头部只是中间素材，不是通用风格肖像。

## 4. MJ `123` 选图规则

此规则只适用于重要角色的 Midjourney 全身和可选头部候选选择，不自动推广到场景生成、下游 Image 2 艺术生成或技术整备。

- 一个固定提示词版本为一组；每组最多三批、每批四张图，最多三组，即最多九批、三十六张候选。
- “当前阶段全部硬门槛”只包括身份可读性、主要体型/轮廓、时代与职业主体、核心服装结构、人体结构和目标画风。推断性表情与 `DEFER_TO_IMAGE2` 道具不计入通过门槛，也不得触发 `Vary`、提示词改写或新组。
- 第一批：提交确定后的提示词并审查四张。任一张同时满足当前阶段全部硬门槛时，选中该张，进入下一工作流程。
- 第二批：第一批无通过项时，只在第一批四张中选择最接近需求的一张，打开该图并执行 `Vary` 栏的 `Subtle`。审查新出的四张；任一张通过即进入下一工作流程。
- 第三批：第二批仍无通过项时，在第一、二批合计八张中选择最接近需求的一张，打开该图并执行 `Vary` 栏的 `Strong`。审查新出的四张；任一张通过即进入下一工作流程。
- 一组结束：第三批仍无通过项时，必须回看本组第一批的共同偏差，据此改写提示词，再以新提示词重新开始下一组的第一批；不得因为第二、三批更接近而跳过第一批证据直接改写提示词。
- 三组结束：仍无通过项时，在全部生成图中选择最接近的一张，标为 `FALLBACK_SELECTED`，列出所有未通过门槛，并进入下一工作流程的修复/候选链。它不是正式身份锁，也不能直接作为正式 `identity_source`、正式角色卡、正式肖像或正式黑白红卡的来源；只有后续 MJ 精修定稿重新逐项通过身份、结构和风格门槛后，才可成为正式身份锁。
- 每次选择必须记录：`group_number`、`batch_number`、作业 ID/URL、四张的审查结论、被选源图、操作（`INITIAL`/`VARY_SUBTLE`/`VARY_STRONG`）、提示词版本，以及新组的提示词改动与第一批证据。

## 5. MJ 精修规则

以全身图锁定：体型、姿态、服装层级、鞋子、配饰、配色与整体轮廓。

可选头部用于：替换不合格的全身头部、补足面部和发型信息、探索更符合描述的面部方案。

优先精修：

1. 背景杂物与不需要的阴影地台；
2. 伪文字、签名和无来源物体；
3. 手、脚、鞋子和人体结构；
4. 衣物边界、轮廓粘连与层级错误；
5. 过度碎片化的头发、衣物纹理和面部细节。

若选定 MJ 全身存在单手背后或手部被遮挡，但其他方面足够优秀，则在通用风格全身转绘阶段用 Image 2 修正为双臂自然下垂、双手完整可见。只修正手臂与手部姿态，不改变体型、头身比、相貌、服装、配饰和配色。

不要无理由改变职业、时代、阶层、核心服装结构与关键配饰。

不要为了补出“和善”“阴险”“威胁”等抽象气质而重画已经通过的身份锁；下游角色卡和肖像必须服从各自锁定提示词的中性/面无表情要求。缺失的便携剧情道具登记为 Image 2 后补项，不反向污染 MJ 提示词。

精修完成且面部通过可辨认硬门槛后才锁定角色身份。必要时从同一张精修定稿中裁出面部身份锚点；如果换入独立头部，则必须先把它确认为精修定稿中的正式脸，再从合成后的定稿裁取锚点。后续所有正式资源从这个锁定版本及其同源锚点派生。

## 6. 下游一致性

- 通用风格全身：保留精修定稿的设计、动作、配色与具体面部几何，只转目标美术风格。参考顺序为 MJ 身份锁定全身、其同源面部锚点（需要时）、通用风格参考；最后一张只控制画风。
- 通用风格角色卡：作为正式角色设计与身份基准。
- 通用风格角色卡的三视图必须使用便于设计核对的中性站姿：双臂自然下垂、双手空置，不得背手、插兜或持有/接触任何道具；正面与背面显示两只空手，严格侧视允许远侧手自然重叠。
- 通用风格角色卡必须含正面、严格右侧面和背面三个头部特写；全身三视图头顶、肩、腰、膝与脚跟基准线一致且不得在上方保留无用途空白；鞋部细节必须展示角色实际穿着批准鞋型时的小腿、裤脚、脚踝和双脚，孤立单鞋不能替代该必需结构图；另可保留零至三张批准配饰、有核对价值的服装构造或批准道具的孤立细节，不用随机衣料裁片填空，且道具不得与人物重叠或被人物拿着。
- 通用风格肖像：仅在路由要求时由角色卡派生；肖像参考只控制风格，不控制人物身份。
- 黑白红角色卡：仅在动画分支触发时由通用角色卡派生；黑白红参考只控制风格，不改变人物与版式。
- 黑白红角色卡：保持黑白红为主色、暗部占比和压缩色阶；皮肤只加近灰度的微弱暖灰褐倾向，不得恢复通用风格的正常肤色，也不得大片纯白。
- 原始 MJ 全身和原始 MJ 头部之间无需统一长相；正式资源之间必须统一。
- 既有角色状态图：从当前批准的通用风格角色卡派生，只改变需求明确指定的状态、表情、动作、损伤、持物、服装差分或环境条件；未要求变化的脸、体型、基础服装、配色与画风保持不变。
- 表情一致性不是概念图、角色卡、肖像之间的身份一致性要求。每类资产只执行其当前锁定提示词；默认角色卡和肖像以中性/面无表情为准。

## 7. 返工路由

| 问题 | 处理 |
|---|---|
| 全身缺头缺脚、姿态/体型/服装主体错误 | MJ 全身重生 |
| 全身整体可用，但头部不清晰或畸变 | 额外生成 MJ 头部 |
| 重要角色的任一 MJ 候选阶段没有一次通过 | 按本文件第 4 节完成当前组的 `INITIAL → VARY_SUBTLE → VARY_STRONG`；第三批失败后才以第一批证据改写提示词并开始下一组，最多三组 |
| 三组 MJ 候选仍无通过项 | 全局最接近图标为 `FALLBACK_SELECTED`，带失败清单进入修复/候选链；未取得通过的 MJ 精修定稿前不得建立正式身份锁或正式下游资产 |
| 全身脸部被大面积阴影遮没、只能看出年龄/发型而看不清具体五官 | 不得跳过头部闸门；生成 MJ 头部或先修复面部照明与结构，再锁定身份 |
| 背景、伪字、轮廓、手脚、鞋子、衣物边界局部问题 | MJ 阶段局部精修 |
| MJ 候选缺少推断性表情或可后补便携道具 | 记录为 `DEFER_TO_IMAGE2` 并继续；不得据此执行 Vary、改写提示词或重开概念设计 |
| 用户已明确选定角色卡、肖像或黑白红卡，却因角色设定中的笑容/道具不完整准备回头重画 | 立即停止艺术循环，冻结用户选图，只做必要比例、尺寸、文件格式与打包处理 |
| 选定全身其他方面优秀，但一只手背后或被身体遮挡 | 通用风格全身转绘时用 Image 2 修正双臂和双手，再进入角色卡 |
| 通用风格转换后只剩“同类人物”而非 MJ 身份锁中的同一张脸 | 返回通用风格全身转绘；同时使用 MJ 锁定全身与同源面部锚点，逐项核对五官几何 |
| 角色卡三视图、三头部特写、对齐、空手要求或细节区错误 | 返回角色卡阶段 |
| 模块化角色卡仅一个视角身份、结构或方向错误 | 只重做该模块；已通过模块保持不变，禁止整卡重生 |
| 模块均已通过但最终尺寸、留白、对齐或排版错误 | 只返回确定性拼版；禁止调用图像模型重绘模块 |
| 用户未明确要求 4K，却进入模块化角色卡路线 | 返回生产路由；改用锁定的默认整卡提示词一次生成 |
| 默认整卡的人物与画风已通过，但比例、尺寸、透明、人物占比或必需外缘结构不符合交付 | 保留并冻结艺术候选；返回技术整备，按需处理抠图、局部扩图/补全、等比例缩放、画布定位和边缘清理，不改写生成提示词 |
| 肖像人物与画风已通过，但比例、尺寸、透明、人物占比或可见边缘不符合交付 | 保留并冻结艺术候选；按需处理抠图、等比例缩放、画布定位和非生成式边缘清理；原生缺肩或截肩不补全、不阻断 |
| 鞋部细节只有一只脱离人物的孤立鞋 | 返回鞋部模块；生成角色实际穿着时的双脚、裤脚与小腿局部 |
| 非必需角色已生成肖像或黑白红 | 可留作历史文件，但不计入当前标准交付，也不能掩盖角色卡失败 |
| 肖像或黑白红局部风格错误 | 仅在对应分支已经触发时重做或精修 |
| 黑白红角色卡皮肤过白、亮面色阶过高 | 以黑白红原结构为底，只给皮肤亮面加入近灰度的微弱暖灰褐并适度压暗；不得恢复正常肤色 |
| 黑白红角色卡皮肤饱和度过高、看起来接近通用风格 | 回到较纯粹的黑白红版本，只保留极轻微肤色色偏；服装、配饰与其他亮面继续保持无彩色 |
| 黑白红角色卡出现大面积红底、红色带或红色边框 | 回到通用角色卡重做；明确禁止大面积红色，只允许细线、徽记或局部小配件作信号色 |
| 肖像被风格参考人物带偏身份 | 拒收；去掉肖像风格参考图，仅用批准角色卡作为图片参考，并以文字复现肖像风格 |
| 用角色卡或全身图裁切、抠图、插值放大代替正式肖像 | 返回肖像生成阶段；不得把正确尺寸、透明通道或身份保留当成肖像风格通过 |
| 机械检查通过，但身份、结构、风格、来源或局部覆盖未检查 | 状态保持 `NOT_CHECKED` 并停止交付；不得写“基本通过” |
| 上游阶段失败但用户明确要求完整流程或探索候选 | 保留失败回执；下游仅生成 `CANDIDATE_ONLY` 候选并记录上游阻断项，不进入正式拼版、正式技术整备或正式交付 |

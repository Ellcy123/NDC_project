# 上下文审美校准

先读取本场景 `ndc-visual-importance/v1`。H0 不设百分比容差；H1 最大 10%，H2 最大 20%，只有写明低显著依据的 H3 最大 30%。按“区域 × 验收项”逐项判断，不跨区域平均；在限内的 H2/H3 不追加纯润色轮次。百分比只用于可测偏差，风格漂移仍需结合角色卡、固定风格块、整场氛围与运行时读图实际判断。

`PROMPT_STYLE_BINDING_GATE` 是提交前的硬合同：固定风格块、哈希、三引用顺序和动态字段边界都不得豁免。实际候选的 `STYLE_LOCK_GATE` 与 `TEXTURE_COHERENCE_GATE` 则以角色放回原场景后的整体可读性、身份、层级和氛围为判断对象，不能把单一局部细节机械地升级为全图拒收。

## 硬性拒收

以下任一问题仍为 `FAIL`，不可由“整体感觉不错”放行：

- 错误媒介/时代语境、明显竞争性的写实或渲染体系，或与原场景相反的主光、透视、色调和空间层级；
- 角色身份、服装关键事实、冻结姿势、比例、支撑接触、互动视线、遮挡、实际 UI 或原场景重建要求错误；
- 候选需要依赖新增人物、虚构道具、替换背景、Alpha 伪透明或任意形变才可使用；
- 影响角色轮廓、脸部辨认、动作阅读或前中后景关系的重复纹理、随机碎点和细节噪声。

## 可校准的软偏差

下列情况可在真实整图和局部检查后判定为 `PASS`，前提是全部硬性项通过：

- 与批准身份卡相符的有限发丝、笔触或材质起伏；
- 未改变角色主剪影、画面信息层级或场景距离感的局部线条密度差；
- 在原场景的光照、对比、色彩、轮廓语言和人物可读性中成立，而不是放大到独立白底才显得“正确”的细节。

视觉记录必须逐项写明：候选与原场景/身份卡的比较、软偏差的具体范围、其未破坏的硬性项，以及 `STYLE_LOCK_GATE` 与 `TEXTURE_COHERENCE_GATE` 的整体结论。不得用“可校准”掩盖未检查或不确定的风险。

## 用户明确艺术放行

用户明确选定或放行某一候选时，该候选可以新增 `PASS_WITH_USER_ARTISTIC_ACCEPTANCE` 记录：引用候选路径与 SHA-256、用户决定的原文/时间、原先的失败记录和逐项整体理由。它只覆盖该记录列明的候选级审美软偏差，不覆盖技术、来源、完整人体、遮挡、Alpha、XY 或最终整场验收；不得删除、修改或倒签既有失败记录，也不得自动推广到其它候选。

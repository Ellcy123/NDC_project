# 人物入景：正式资产生产

## Photoshop MCP 强制前置

本 Skill 第一次实际调用 Photoshop MCP 前，必须完整读取当前环境的《PS MCP 操作参考手册》：维护工作区从项目根解析 `PS_MCP_操作参考手册.md`，工程镜像从仓库根解析 `production/art_pipeline/PS_MCP_操作参考手册.md`。在当前场景作业及提取能力合同中保存实际手册路径、版本、SHA-256 和当前会话能力快照；两处均不存在或哈希不一致时不得以历史记忆继续操作。手册负责通用效率、抠图、Alpha、软硬边路径、单引擎、超时回退和视觉/技术验收；本 Skill 的非生成提取合同、整场生产和交付门禁继续优先。实时目录只允许执行 supported 能力，手册本身不增加操作授权。

点击后交互状态必须看向镜头、回应玩家。active 正式提示词明确“头部自然转向镜头，双眼直视镜头”，生成后实际检查头部朝向和双眼视线；仅抬眼或看向画外人物判为不符合。保持合理的身体方向、支撑和手部道具动作；未点击 idle 与纯剧情人物间交流按各自剧情执行。

接收已确定的整场白模后，本阶段全权承担后续生产与交付：先完成并冻结同一场景全部必需角色／状态的正式生成或合法复用源，再统一进入提取、去背景、注册、合成及必要返修；不得生成一个角色就先处理一个角色的 Alpha。按冻结白模校正位置、整体大小、头身比、动作和遮挡属于本阶段职责，不要求参考任务持续监控、复核或代修；按白模纠正生成偏差不属于重设参考。仅在白模自身核心关系错误且必须改变已确定方案时，附明确证据回传参考返修。下游自行登记结果并接续已就绪场景，不等待上游逐步批准。

用户默认是需求与结果的决策者、审核者，不是 Photoshop 生产操作员。不得把抠图、Select and Mask、通道、蒙版、笔刷修边、保存导出或其它可执行生产劳动指派给用户，也不得以“请手工完成后回复已完成”作为继续生产或交付的前提。文档中的“人工 Photoshop 路线／人工交接”只允许指向用户已为当前资产明确指定的人工制作人员，或用户对当前资产主动明确选择亲自操作；历史协作、已打开 Photoshop、`requires_user` 状态和一般性授权均不能推定该选择。登录、验证码及平台强制身份验证仍可作为必要人工节点，但不能扩张为图片制作劳动。

## 整场角色先生图门禁

一个场景 revision 以冻结 scope 中全部 `case / snapshot / actor_pose_id` 的并集为正式生成范围。Terra 按已确认的远近层次和批次顺序生成、回收并逐个完成提取前视觉审核；单个角色／批次完成后只保存原始下载、网页回执、候选结论和冻结 SHA-256，继续本场剩余角色，不调用正式角色抠图、Remove Background、Select Subject、Alpha／蒙版、注册、接触合成或最终场景合成。经当前来源规则允许直接复用的正式角色／状态，可用相同字节及复用证据满足对应范围，不为形式完整重复生成。

只有建立 `SCENE_CAST_GENERATION_GATE: PASS` 后才进入整场提取阶段。该门禁必须逐项列出冻结 scope、每个必需角色／状态、生成或复用来源、原始文件、来源回执、提取前视觉审核及 SHA-256，并证明没有缺失、失败、待回收、结果未知或尚未冻结的项目。任一项目未就绪时，继续本场其它角色的生成、回收与审核；已生成角色不得抢先进入 Photoshop 提取。一个角色用尽生成预算或受阻时，保存整场检查点并继续不依赖其结果的生成工作，但本场提取门禁保持失败；不同完整场景在来源和记录隔离时可独立推进。

旧任务若已经对部分角色完成提取，不删除、不覆盖既有结果；从当前状态起停止本场新的角色提取，先补齐并冻结尚缺的全部角色／状态，门禁通过后再恢复统一提取阶段。该顺序只约束正式角色生成后的抠图去背景链，不禁止参考阶段为白模或生图输入执行已授权的准备工作。

## 多路线提取耗尽门禁

`SCENE_CAST_GENERATION_GATE: PASS` 后才能为本场角色开始透明提取。透明提取不能把一个按钮、一个动作或一个不合格输出当作 Photoshop 整体能力结论。每个角色开始提取时，必须按当前《PS MCP 操作参考手册》第 4.3 节建立 `route_exhaustion_log`，结合当前命令目录与人物的硬边、发丝、半透明材质，登记原生 Alpha、直接透明动作、语义选区到 RGBA、通道／计算及其它受支持且适用的非生成路线。对每条端到端命令均为 `supported` 的适用自动路线至少在新副本上实测一次，并记录命令、回执、输出或精确失败点；同一原样命令最多重试一次，但必须换测其它独立路线。只有正式 RGBA 已通过，或所有适用路线均已有实测／不适用／不受支持证据，才可停止提取探索。

“选择主体”形成选区但当前没有受支持的选区转 Alpha 手段，只判定该 `selection_to_rgba` 路线受阻；“移除背景”导出后仍保留矩形场景背景，判为 `PROVISIONAL` 或质量失败并保留文件，不能记成没有输出。前者不阻断直接透明动作、通道等路线，后者不阻断其余适用路线或 provisional 下游。未完成 `route_exhaustion_log` 不得登记整体能力失败、停止整场、跳过后续角色或把操作交给用户；Computer Use／界面操作只有当前任务另有明确授权时才可使用。

## 提取不完整仍推进的 provisional 分支

角色候选已经通过身份、动作、完整人体、服装与风格等提取前门禁，且 Photoshop MCP 已实际产出可打开的非生成 RGBA 后，即使边缘仍不完整、存在残留／误删、软边无法确认或操作者把握不足，也不得丢弃结果、留空或停止后续整场工作。保留提取前原图的精确字节、尺寸和 SHA-256，另存尝试 RGBA、可恢复 PSD、实际蒙版／路径／动作证据、Alpha 多底预览和逐区缺陷说明，标记 `PROVISIONAL_EXTRACTION_PENDING_USER_REVIEW`；后续尝试新建版本，不覆盖原图或旧 provisional。

该状态允许继续明确标记的 provisional 注册、遮挡、接触、阴影、全场合成、XY、重建与整包视觉检查，并把原图、尝试件、恢复件、缺陷和派生结果交付到 `工作过程文件` 下独立的“待用户审核交付包”。所有派生件继承同一状态和源哈希；它们不能写入正式目录、不能满足正式 PASS，也不能把未通过的 Alpha／边缘改写成已通过。用户审核、修正或后续自动提取通过后，从保留原图或明确选定版本建立新修订并重跑受影响门禁。若根本没有合规 RGBA 输出，仍按能力阻断继续其它独立工作，不伪造 provisional 文件。本节不放宽角色语义、身份、姿势、完整人体、场景关系或生成来源门禁。

两态演绎必须保留白模确定的可见视角及最小自然动作：应只见后脑勺时不擅自露侧脸；侧身转头回应镜头时不改成全身正面。按 [状态动作连续性](../ndc-character-scene-integration/references/state-variant-assembly.md)检查头眼、肩胯和单脚转移的配合，不能仅凭 active 标签或视线文字放行。

同一快照三人及以上同时在场时，读取并执行[三人及以上同场背影构图门禁](../ndc-character-scene-integration/references/multicast-back-composition.md)。正式生产必须继承白模锁定的非 active 前景／近中景背影角色、深度和可见背部关系，不得因模型倾向正脸改成正面或侧面；`formal` 候选与 `final-composite` 全场各运行一次 `MULTICAST_BACK_COMPOSITION_GATE`，并复核真实 UI。只有用户对准确 scene/snapshot 的明确改写可例外。

白模顺序：初次生成时包括隐藏部位的完整人体，保留未裁剪母层；随后按真实遮挡关系裁剪派生层或制作蒙版，审核裁剪后的场景参考。正常裁剪不算缺失，不要求补回场景中本应被遮住的像素；小瑕疵容错不取消初始完整生成。正式角色同样先生成完整母层再应用遮挡。

执行前读[对话任务独立额度](references/task-budget.md)：新对话完整新额度，其他对话的资产历史不扣减；已授权工作直接推进，不索要例行答复。此用户最新规则优先于旧预算说明。

生产编排任务固定为 `gpt-5.6-terra`，`thinking: xhigh`，由 [参考协调任务](../ndc-character-scene-reference/SKILL.md) 通过实际任务工具指定。Terra 负责判断、操作、回收与验收，但正式像素只在**受支持的可见浏览器中的 `chatgpt.com` 网页版 ChatGPT**生成；浏览器可为内置 `iab`，或 Computer Use 当前支持且用户已指定/授权的外置 Chrome、Edge。用户指定浏览器优先；未指定时选择当前健康、已登录且可追溯的浏览器。网页模型档位默认选择“极高”；若当前账号／页面没有“极高”，选择实际可用的最高档位，不等待解锁、不绕过账号限制。该网页后端是保持当前 NDC 角色画风一致性的必要生产路径，禁止调用 Codex 内置图片生成工具、图片生成 API、其它站点或其它生图后端替代。引用 [入景共享规则](../ndc-character-scene-integration/SKILL.md) 和 [入景阶段交接](../ndc-art-stage-pipeline/references/integration-pipeline.md)，先claim唯一场景，检查原来源、完整范围、pre-generation ledger、重要度配置和剩余次数。旧任务或重复消息不得重复领取或重开生产。

读取 [制作节奏](../ndc-character-scene-integration/references/production-cadence.md) 及 [完整流程](../ndc-character-scene-integration/references/full-workflow.md) 从“Actual generation handoff”到最终交付；不要从需求盘点重跑参考阶段。

- 全场按原远近层次、完整角色和交互单元生产，始终回到同一完整场景判断。保持各状态角色联动，不能拆成互不知情的角色任务；三人及以上快照保持已锁定的非 active 前景／近中景背影角色，并在正式候选及最终合成复核对应门禁。
- 遵守[白模放行与正式完整性](../ndc-character-scene-integration/references/whitebox-acceptance.md)：已放行的小型遮挡/缺失不退回参考。实际提示词要求同姿势、位置、比例和头身比下生成完整角色，补全列出的缺失，结果逐项实查，不能照抄白模缺损或把提示词要求当作完整性通过。
- 每次正式提交、结果回收和未知状态处理均按[网页版 ChatGPT 生图](references/chatgpt-web-generation.md)执行。一个完整场景 revision 使用一个专用 ChatGPT 网页对话；每次提交前先生成不可覆盖的 submission packet，按 `local-whitebox-crop → untouched-full-scene → approved-character-card → full-prompt` 固定顺序逐项核对并提交，不依赖历史上下文暗示。已授权正式生产中，包与门禁通过后由任务自动选择最高可用网页档位并直接上传、提交，不向用户逐角色或逐次询问“是否发送／请回复发送”。浏览器按用户指定及当前健康、登录和可追溯状态动态选择，不设置“先内置、再外置”的固定顺序；接管已有外置标签页时先枚举并按完整对话 URL 认领，动作报 session ownership 错误时重绑而不是判定浏览器失联。若当前恰为内置浏览器且首次明确确认该载体无法回收已生成结果，立即转到已登录同一 ChatGPT 账户的健康外置浏览器，打开同一专用对话验收和下载，不在故障载体重复等待，也不另开对话或重发。控制传输失效按引用中的有限重试和重置规则处理；完整缓存只能保存为非正式恢复候选。下载网页提供的原始结果到同一过程包，保存 v2 可追溯回执；浏览器预览截图、已加载缓存或恢复候选均不能冒充原始下载文件。
- 实际生图前guard并在原成本journal同一job登记attempt，结束或结果未知立即记实；多人调用按原规则在相关单元计入，统一提交标识用于全场去重统计。不得另建一份零计数日志。
- 每次编辑正式生图提示词后、写入模型 `attempt` 前，必须运行[提示词风格绑定门禁](references/prompt-style-binding-gate.md)，保存当前提示词、固定风格块、三引用角色和动态字段的检查回执。仅 `PROMPT_STYLE_BINDING_GATE: PASS` 可提交；任何固定风格块哈希不符、缺失/改写、引用顺序漂移，或动态字段含反向风格要求均为 `FAIL`，不得用后续出图审美检查补救。
- 实际像素的 `STYLE_LOCK_GATE` 与 `TEXTURE_COHERENCE_GATE` 按[上下文审美校准](references/contextual-review-calibration.md)作整体判断：提示词合同、身份、构图、支撑、场景氛围、遮挡、UI、Alpha 与 XY 仍是硬门槛；与身份卡一致且不破坏场景层级的局部笔触/发丝等软偏差不得机械一票否决。每次软偏差放行必须在当前候选的真实视觉记录中说明整体一致性、受影响范围及为何不构成画风漂移；用户对具体候选的明确艺术放行必须保留为新增且可回溯的记录，不能回写或删除原有失败记录。
- contextual结果先按重要度配置分流：H0 失败立即拒绝，H1 超过 10% 才修复或重试，H2/H3 在 20%/30% 上限内直接接受且不追加润色；禁止跨区域平均。每个结果完成审核和冻结后继续本场剩余生成，不能立即提取；整场 `SCENE_CAST_GENERATION_GATE: PASS` 后，进入 RGBA 提取前必须执行[非生成提取能力门禁](references/non-generative-extraction-capability-gate.md)，并保存 `EXTRACTION_CAPABILITY_GATE: PASS` 回执。门禁以可复核的**结果**为准，不指定“选择主体”或任何单一 Photoshop 按钮。可使用真实主体/对象/快速选择与图层蒙版、已安装的非生成去背景动作、色彩范围、通道/计算得到的 Alpha、既有蒙版修整、Select and Mask，或已明确指定人工制作人员完成的 Photoshop 精修；每种路线均须保存对应的原生操作、PSD/PNG 和 Alpha/蒙版证据。`selection.polygon`、自动坐标轮廓、粗略矩形、像素复制、仅切换图层可见性，以及动作成功/棋盘格/透明像素统计本身，均不得作为人物边缘识别或正式透明提取完成的依据。动作可在源图未保存副本上成为正式候选路线，但只有其实际输出无场景残片、无生成像素，并通过全身及发丝/半透明边缘、手、鞋和高对比衣物边缘的局部审阅后才可正式放行；不要求再把动作结果强制改造成“主体选择”。人工 `Select and Mask`、通道或笔刷修整必须满足上文的人工制作人员授权边界，并登记交接及保存的 PSD/PNG；不能以“之后人工处理”替代结果证据，更不能默认要求用户执行。一个自动提取候选不合格时，必须按本 Skill 的多路线门禁在其它适用且受支持的合规非生成路线中继续，不能从一次失败直接升级为用户任务或整体能力失败。若已实际导出但结果不完整或低置信度，按本 Skill 的 provisional 分支继续整场派生与待用户审核交付，同时继续尚未实测的适用路线；若路线耗尽日志证明所有路线均不可用、且没有合规 RGBA 输出，才以提取能力失败登记，保存检查点并继续同一整场内不依赖该透明层的已授权工作。两种情况均不得省略角色、伪造 RGBA，或把未完成整场登记为正式 PASS。任何路线均须导出 PNG RGBA 并随后实测 Alpha；仅“Photoshop 已连接”、仅能打开/导出文档或尚未验证的人工意图均为 `FAIL`。正式透明层通过后才可进入正式图层顺序、合成与归档；所有PS连续段使用本机已配对原生 MCP，确认无在途/未知命令并安全保存审阅快照后才交棒。
- 自动提取合同还必须证明当前源图能由命令目录中 `supported` 的受控打开、置入或导入能力进入当前 Photoshop 会话。任何 `experimental`／`requires_user` 源图入口，以及将源图复制到导出目录后冒充导出，均为 `EXTRACTION_CAPABILITY_GATE: FAIL`；可选入口动态取决于当前真实目录，不能把某个按钮或一次历史成功固定为唯一方法。
- 像素修复只恢复已批准姿势和几何目标；若必须更改姿势、落点、尺度依据或多人关系，回传 `FAIL`、`return_stage: reference`，由Astra修订相关参考。不能靠任意扭曲、改家具或降低门禁继续。
- 每个实际修改图像完成保存、技术和全图/相关局部审阅再推进。局部遮挡修改复用未变的独立母层和尺度依据，只重查受影响角色、交互与整场快照；新的合成图仍须查看。
- 原post-generation ledger、身份/风格/纹理、完整图层、真实UI、Alpha、XY及原尺寸重建全部通过后才回传PASS并按原规则归档。技术和合同测试不作艺术批准。

每次结果回收后claim-next已READY完整场景；没有就绪场景就结束本轮，由Astra以后唤醒同一任务。人工节点与未知外部操作遵循原阻断规则，不占PS等待；不自行建立后台服务。

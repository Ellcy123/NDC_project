# 阶段审核与严格复用

真实视觉审核沿用 ndc-stage-visual-self-check/v1：stage_id、reviewer、reviewed_at、role、inputs、outputs、views、criteria及visual_check_status。输入输出有路径和SHA-256。结合批次 H1/H2/H3：H1 使用运行时、whole_100与按 `local_200_required` 指定的局部检查；H2 使用运行时与whole_100，异常才局部放大；H3 以运行时为主，异常才升级。未写 importance 字段的旧记录仍要求 whole_100 与 local_200_or_tiles；新记录必须写级别、容差及所需依据。同一组真实观察可被多个相容标准引用，不要求重复打开或重复截图。未检查记NOT_CHECKED，失败记FAIL；脚本不得创造视觉PASS。

每份记录可以同时承载内容、身份、风格／纹理、Alpha和本阶段技术报告的引用，避免另写同义表单。缺失的专用检查必须实际执行：Type7保留源场景并排、原高度视角和直接生成证据；热区一份PASS仅对应一张PNG，保留Alpha、棋盘底、父图叠加、完整性与相邻交互物排除记录。所有可拾取、线索和环境叙事道具都必须实际检查本体及全部归属阴影，存在热区时要求联合轮廓完整覆盖。对地图直接拾取且拾取后消失的道具，同一记录还必须哈希绑定原场景、无道具承载物状态、道具＋全部道具归属阴影独立层和拾取前结果，并实际检查承载物及其自身阴影不进入 Map、Map 覆盖独立层全部非透明内容、按 XY 合成逐像素重建拾取前场景、移除后承载物永久保留且无道具／道具阴影残留或修补接缝；缺少独立分层或无道具承载物状态时不得以“待程序接入”放行。Type 7 子物品仍按菜单父图合同检查，不套用地图直接拾取的承载物三层门禁。

## 新五阶段绑定

真实审核完成后，将workflow_state.py binding输出的对象原样写入该记录的workflow_binding。对象绑定artifact_id、role、当前图像哈希、实际引用事实摘要、验收要求摘要及父图哈希。已接入场景索引的第三阶段非Icon产物还绑定scene_release_contexts，涵盖所属场景完整关联事实、来源、前置图像及审核版本。此命令仅计算绑定数据，不审核图像，也不写PASS。

workflow_state.py validate会同时确认：

- 当前图像和原审核输出字节相同；审核角色相同且涵盖本资产要求。
- 相关事实及允许差异没有改变，父图和派生依赖仍通过且没有用户否定。
- 所有原始审核输入和审阅图仍能恢复，现行逐阶段校验通过。
- 正式副本与已审核字节相同；同名、同尺寸或同一个摘要不能代替这些检查。

一次复制可以直接引用该记录，不要求把复制当成一次新生图审核。任何缩放、裁切、合成、Alpha调整都产生新输出，需要检查新增风险并建立当前记录。未变的内容检查可以引用完整母版，不能用母版PASS代替缩小后边缘检查。

场景索引首次接入不会重画已有合格图，也不会自动给旧记录补PASS。旧第三阶段记录若尚未核对新增关联范围，只补查这部分缺失证据，保留原图及已有有效观察，再形成当前完整绑定；不得仅运行binding覆盖旧摘要来掩盖关联变化。相关事实、父图字节、前置审核或关联来源改变后，即使场景PNG字节未变，也须先复核新增影响。无关场景的未完成／失败图不使本场景审核失效。本场冻结后可先开放本场热区；全批次Icon、全部热区和最终交付门槛仍独立执行。

批次artifact.acceptance_contract列出本阶段应检查的名称与具体标准；记录criteria须逐项实际满足。A字段在语义母版完整核对；B按事先允许差异检查；C按整体风格判断。不要将跨阶段全部标准复制到每个细小确定性导出。

## 最终复查

最终校验完整的需求—图像—父图—坐标—正式目录对应关系，并做跨状态、跨角色的实际联组判断。已有相同范围的联组审核可以复用，但缺失联组证据必须补查。已失败且退出选定链的历史候选只保留记录，不要求为它们取得PASS才能发布合格替代品。

workflow_state.py不证明美术质量，只验证交接与审核证据；validate_formal_release.py继续验证文件角色、尺寸／Alpha、坐标和父图像素。final_visual_check.py在--batch模式按明确published_path和审核绑定核对，拒绝仅凭历史文件哈希覆盖当前拒收。

旧批次未迁移时仍可调用旧命令检查历史证据；旧命令结果不代表已满足新五阶段规则。新批次发布必带--batch，合同可保存workflowBatch指向同一batch.json。

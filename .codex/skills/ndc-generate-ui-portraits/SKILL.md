# NDC 角色 UI 肖像

分类：静态美术 → 角色 → UI 肖像。工程入口为 `.codex/skills/ndc-generate-ui-portraits`；支持文件全部从本 Skill 目录解析，不依赖个人目录中的脚本。

先检索过去章节是否已有同角色 UI 肖像，存在则复用。仅对未命中的角色，从已批准的角色卡和通用肖像制作一张 **3:4、完整胸像、职业场景背景**的 UI 母图，再分别输出 **big 222×240** 与 **small 106×120**。两版保留场景背景，默认 PNG/RGB，不走表情透明底或绿幕流程。

## 范围与入口

- 本 Skill 不新设计人物，不生产通用角色卡/通用肖像，也不制作表情库。仅在新制作分支缺少上游资产时输出 `UPSTREAM_CHARACTER_ASSET_REQUIRED` 和具体缺项，交角色生产流程；不把角色卡局部放大当成通用肖像。已命中的历史 UI 资产按复用分支处理。
- 上游通用肖像允许截肩；本流程按用户 UI 需求另行生成完整胸像母图。不能回写为所有通用肖像都必须补肩，也不能将小尺寸 UI 成品充当表情母版。
- 用户仅要求提示词、准备在 ChatGPT 手工生成，或仅要求维护 Skill 时，不调用图片生成。用户明确要求 Codex 执行，或明确要求本流程批量生产/工程衔接时，按已有授权推进；创建 Skill 本身不授权出图。
- 编制任务前读工程 `canon_manifest.json`、对应策划人物设定、角色索引及项目规则。工程采用路径配置时，读 `docs/美术生产工作区.md`，用 `ndc_art.py paths` / `skill ndc-generate-ui-portraits` 定位；没有配置不要套用别人的盘符。当前本机工程为 `D:/Codex/NDC/NDC_project`。
- 过程件进入项目外受管工作区；本机工作根须在 `D:/Codex/NDC/工作过程文件` 下，按角色、Unit、可搜索中文名称分组。不得写入 `D:/PMH/工作` 或 `D:/PMH/ndc`。正式主档归档、工程转入授权和任务收尾遵循当前项目规则；不得擅自关闭或清除待返工任务。

## U0 前置：过去章节资产检索与复用

每次按章节编制需求，必须在寻找新生成用角色卡、写提示词或调用生成工具前，先检查所有早于目标章节的已交付／已入游戏 UI 肖像。依当前项目配置定位正式游戏资源、已确认交付资产及历史章节 UI 目录；不要仅搜索当前章节，也不要将后续章节称作过去章节。用户指定来源时优先遵从。

按角色正式身份、姓名／别名和资产映射匹配，核对跨章节 NPC ID 与文件 stem；同名文件不等于同人。只将该角色自己的 UI 肖像作为命中，不把通用肖像、表情、角色卡或其他人物的临时占位图算作其已有资产。

- 命中同角色既有 UI 肖像：标记 `REUSE_EXISTING`，直接沿用原始 big／small 文件或既有资源引用，保持字节、构图、画风和命名映射。新批次风格参考只约束需生成者，不构成重画、调色或重新裁切旧资产的理由。用户明确指定的重制例外优先于默认复用。
- 只有一版存在、文件损坏或规格缺失：保留可复用部分并列明缺项；先查同一历史交付的配套版本或母图，不因缺一版自动重做完整的一对，不放大 small 充当 big。
- 未命中：记录检索范围与结果，再进入下述 U0–U3 新制作分支。未检索不能直接标记“无历史资产”。

需求表记录角色、目标章节、检索过的历史章节／目录、命中来源章节、big／small 路径与 SHA-256、身份匹配依据和 `REUSE_EXISTING`／`GENERATE_NEW`／缺项状态。复用不要求重新生成人物卡或补造历史母图、裁切及审核记录；本次只核对身份、文件可读性、两版规格和复制／引用的正确性，并如实记录来源，不改写源目录。新生成候选已存在但随后决定复用时，候选留作过程历史，不混入本次交付。

## U0 新制作输入与来源锁定

记录角色 ID、正式名字/文件 stem、Unit、角色卡路径与批准依据、通用肖像路径与批准依据、两者 SHA-256、策划职业/身份的文件及位置。用角色索引核实人物与版本，文件名或最近修改时间不等于批准。

三图顺序固定：**图1 通用风格角色卡 → 图2 UI 肖像风格参考 → 图3 该角色通用风格肖像**。图1锁相貌与设定，不继承其动作和视角；图2只锁画风；图3为本次生成基础。图2默认使用 [assets/ui-portrait-style-reference.png](assets/ui-portrait-style-reference.png)，它由源 Word 唯一内嵌图片原样提取，来源和解释见 [references/source-analysis.md](references/source-analysis.md)。有用户新指定参考则记录并替换当前任务的参考，不覆盖历史。

对照三图检查脸型、眼鼻口、发际线、年龄、服装与配饰。若图1和图3的批准身份冲突，先解决来源，不能融合两个人；图2人物不得成为身份源。

## U1 生成 3:4 母图

读 [references/generation-prompt.md](references/generation-prompt.md)，使用保留的原始风格段与本流程的约束说明。角色背景从已核实职业/身份推导并记录依据，不凭衣服猜职业或引入剧情剧透。背景为黑色电影照片写实、安静的浅景深场景；人物继续采用参考图的插画画风，不能全图照片化。

身体向一侧偏转约 15°，头正对镜头，面无表情直视；完整肩膀、上半部分手臂和胸腔以上外轮廓在母图中可见。背景覆盖整个画布，保留足够空间供两种头像裁切。母图缺结构、侧脸或身份漂移时，返回三张冻结输入重生，不能从失败候选接力生成，也不能在最终小图里补画。

审查母图整图原生 100% 和局部至少最近邻 200%（全图纹理须无遗漏原像素覆盖），并与源目录的 big、小图分别横向对比。使用 [references/review-and-delivery.md](references/review-and-delivery.md) 的项目，不以“看起来差不多”代替逐项判定。通过后冻结母图文件和 SHA-256。

## U2 同母图双规格裁切

读 [references/profiles-and-tools.md](references/profiles-and-tools.md)。查看原版辅助线及示意图，实际标注母图两眼中心、下巴底点；脚本不自动识别人脸。

| Profile | 画布 | 对齐优先级 | 参考线中心 y，左上为 0 |
|---|---|---|---|
| big | 222×240 | 下巴黄线 → 眼睛绿线 → 头顶红线大致位置 | 下巴 192.5；眼睛 106；头顶 7.5 |
| small | 106×120 | 眼睛红线、下巴绿线 | 眼睛 51.5；下巴 108.5 |

头顶线是软参考。帽子、高发型可超出最终画面；不能为了保全帽顶破坏眼睛/下巴对齐。完整肩膀要求适用于母图，最终头像允许按示意裁切。

两版都直接从同一冻结母图进行等比缩放、位移、裁切；small 不从 big 缩小，禁止拉伸、旋转、重画或额外锐化。裁切窗口必须被母图覆盖；分辨率不足或窗口越界时返回母图阶段，禁止补黑边、白边或镜像背景。工具默认禁止上采样，这是防低清的工程保护，并非源 Word 明文要求。

使用自带 `scripts/ui_portrait.py` 制作两版候选、辅助线叠加预览、200% 审阅图与技术回执；仅依赖 Python 3.10+ 和 Pillow，详见工具说明。脚本只产生 `TECHNICAL_PASS`，视觉状态始终为 `NOT_CHECKED`。

## U3 逐张复核与交付

每一生成、裁切、修复、包装步骤结束后立即做真实视觉自检并绑定当前输入/输出 SHA-256；任一 `FAIL`、`NOT_CHECKED`、视图缺失或哈希过期，不得进入下一正式步骤。技术数据、像素重建或哈希一致均不证明视觉通过。

依 [references/review-and-delivery.md](references/review-and-delivery.md) 完成 big/small 原尺寸可读性、身份与画风连续性、眼睛/下巴实际位置、背景与无辅助线残留审核。用工程公共 stage/texture/final 验证器校验真实审核记录；单独枚举全部实际步骤，防止末端只检查文件而漏掉母图阶段。

交付分开放入 `big/<正式stem>_big.png` 和 `small/<正式stem>_small.png`；保持既有角色大小写、空格和正式 stem。文件名另有合同则按合同执行，并记录映射。母图、提示词、标注、回执、辅助线叠图、失败历史保留在对应过程目录；最终图绝不含辅助线。用户未要求工程转入时不自动复制；通过自检不冒充用户已选择某个字节版本。

对用户输出：来源与当前状态、可复制提示词（仅提示词任务）、两版文件链接（实际生产时）、技术/视觉结论和未解决项。只产出了 Skill 或做了模拟测试时，明确没有实际生成人物。

# 人工回流与极简导出合同

## 输入边界

本合同只接受角色入景人工回流 PSD。优先输入是角色白模节点交付包中每场唯一的 `performance_editable_source`：原场景画布保持原尺寸，原场景、实际 UI 以及冻结 scope 中每个 actor/pose 都是可独立开关和修改的命名层或组，并保留节点确定的位置与比例。新节点 PSD 在上游必须只装入已通过连续三维体积、可读完整解剖及重心／承托门禁的白模；彩色三维白模可以合格，扁平／关节代理、联合预览裁片和仅靠像素阈值通过的图片不能成为节点 PSD。局部返修的未涉及角色应保留已认可 baseline 的来源和变换。该上游标准不授权本 Skill 在用户声明定稿后重复审核。

用户也可以直接指定另一个角色入景 PSD。不要把 PNG 合成预览、扁平图、道具 PSD 或普通生产候选推定为人工回流工作区。

## 定稿声明后的唯一输出

用户明确说明图层、阴影、位置和比例均已完成后：

- 只读取资产需求、PSD 图层名、图层边界和画布坐标；不检查画面正确性。
- 每个必需人物层和阴影层按现有像素、透明度、位置、比例原样导出为需求指定格式。
- 场景就绪 PNG 的文件名以 `__XY_x<int>_y<int>` 结尾；XY 是导出层在原场景画布中的整数左上角。
- `XYposition.txt` 每行使用 `<文件名stem>\t<X>,<Y>`，顺序与资产需求一致。优先运行 `scripts/write_xyposition.py`，不要手工再建第二份清单。
- 完成后直接交付，不附审核结论、过程证据或额外报告。

本分支不接入角色生产 Skill 的回收、提取、合成、验收、候选和 finalizer，也不调用流水 Skill 的 `manual_review_node.py return`。用户定稿声明不新建 revision，不写 `USER_RETURN_ACCEPTED_FOR_PACKAGING` 或 INPUT_GAP。

## 阻断范围

只有 PSD 无法打开、需求中的必需层不存在，或同名层导致角色／状态映射不唯一时，才阻断对应输出并报告精确文件／图层名。不要转成画面审核、自动修复、生图或全场返工。

同名目标文件的处理服从当前任务明确的替换范围；未授权替换既有正式资产时，不覆盖无关文件。道具人工回流使用独立的 `ndc-prop-manual-return`，不得把本角色合同复制过去。

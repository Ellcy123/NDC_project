# SC4002 与 SC4003 人工回流案例归纳

这些案例记录 2026-09-15 两场 Unit4 人工定稿 PSD 的机械导出经验。路径统一使用项目根变量；数字只说明已发生案例，不应复制到别的场景。

## SC4002：Type6、Type7 与子 Map

来源位于 `{DELIVERY_ROOT}/道具/Unit4/SC4002/`，过程证据位于 `{WORK_ROOT}/道具/Unit4/SC4002_机械导层预检_20260915/`。

4113 的 Type7 权威层是组内 `prop_2`。原始像素边界为 `(1952,866)-(2360,1274)`，但用户定稿的 12px 白色描边向外扩展，所以交付视觉范围为 `(1940,854)-(2372,1286)`、尺寸 `432x432`。正确做法是导出该层及其效果；整张文档合成裁图会把无关兄弟层烘焙进去，已经作为错误路线排除。

4113 的子 Map 直接来自组内 `map`，全场景边界 `(2079,997)-(2223,1150)`、尺寸 `144x153`。它相对 Type7 视觉左上角的局部偏移是 `(139,143)`，但交付文件与 XY 仍使用全场景 `(2079,997)`。可见 RGB 与 Type7 对应位置一致，Alpha 0 下 RGB 清零不改变画面。

4113 Type6 图层名曾带 `x1998` 注释，但真实视觉左上角是 `(1959,970)`。最终文件名和 XY 使用真实位置，而不是沿用层名注释。根 `XYposition.txt` 同时登记 4112、4113 的 Type6、Type7 与 Map；Type7 虽无 XY 文件名尾缀，也不能漏掉坐标。

可复用结论：分别导出用户权威层；图层效果决定视觉边界；坐标以当前画布事实为准；Type6／Type7／Map 三者分别登记并显式关联。

## SC4003：同组承载层、子 Map 与 Big/Icon

来源位于 `{DELIVERY_ROOT}/道具/Unit4/SC4003_法院档案室_白天__Court_archive_day/`，过程证据位于 `{WORK_ROOT}/道具/Unit4/SC4003_机械导层导出_20260915/`。

4115 不是普通 Type7 菜单，而是同一场景中的承载关系。`map1` 是非二级菜单场景承载层，边界 `(1579,756)-(1725,844)`；原子项 `map` 后由用户人工改名为 `map2`，边界 `(1655,781)-(1711,826)`。交付配置固定为 `SC4003_4115.map1 -> SC4003_4115.map2`，两张 PNG 和两条全场景 XY 均独立保留，不能因同属 4115 而合并或互换。

4116 的 `map` 独立导出，左上角 `(1846,818)`。4111 的 `big` 由用户指定的宝丽来层直接替换根 Big；回流源画布为 `616x618`，而线索宝丽来最终规格为 `620x620`，因此在人工回流支线内直接用透明画布补齐并保持内容完整。这是随导出完成的常规调整，不另设门禁，也不能把回流源尺寸直接当成交付规格。Big 不写 XY。Icon 只从规格已归一的当前 Big 作确定性裁切／缩放，保持透明像素与安全框，不调用生图或重设计。

用户进一步明确：这种人工处理后的回流导出直接进入指定交付目录，不再额外建立 `交付候选` 文件夹；只有确实需要保护旧文件时才备份。必要的命名与哈希记录留在工作过程目录，不复制整套交付图片。

可复用结论：同组多 Map 必须显式命名和父子关联；人工改名同步文件 stem、XY 与配置键；Big／Icon 与坐标型 PNG 分开处理；Big 回流后仍需满足最终 Profile；人工回流不再制造候选副本。

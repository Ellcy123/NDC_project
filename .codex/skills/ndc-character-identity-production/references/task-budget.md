# 对话任务额度与自主执行

2026-09-09用户直接指令；优先于本Skill及其引用内旧的跨任务扣数、未知历史按耗尽处理、独立新任务须再次声明及例行答复要求。

- **只以真实对话任务ID判断新旧。新对话自动拥有本Skill完整新额度**，同一资产、旧候选、旧失败图在其他对话中的生成次数不扣减新额度；不要求用户再确认或追加授权。
- 同一对话内的继续、恢复目标、模型/等级切换、跨日、改名、换位置和阶段切换，仍累计本对话已发生的调用。不得伪造ID或仅为刷新额度自行创建对话。
- 已授权工作自行检索来源、核对清单、选择候选、修复并推进，不索要例行确认、历史次数核对或追加额度的答复。能力受阻先做独立工作；本对话额度耗尽时保留候选及失败原因、继续独立项并报告，不建立等待答复的关卡。
- 各Skill每工作项/阶段的原次数上限与计数单位保持，但限定在当前对话内。保留稳定资产/job ID和原始追加日志；每次调用标记实际task_id，按对话分别统计。其他对话的历史仅追溯，不影响当前剩余额度。平台账号用量和限流不属于工作流额度。
- 优先读取CODEX_THREAD_ID；缺失时执行者从真实任务工具或本地任务记录获得，不向用户询问。未标归属的旧调用先由执行者查来源并追加归属证据，不改写旧事件；恢复同一对话必须计入它的真实调用，其他任务未知历史不得推定新额度耗尽。在途结果未知仍先核实，防止重复提交。
- 候选按对应必需产物去重计入制作覆盖；未复核、已检查未通过、有效PASS分列，交付就绪比例单独统计。候选不自动通过质量检查；真实依赖、来源保护、技术/视觉复核、PS队列及安全交棒继续执行。

## 使用共用计数脚本的流程

通用art_workflow_state.py在新计划头记录conversation_task_id，每个attempt保存实际task_id；status输出budget_task_id及当前对话的used。计划原task_id继续作为既有生产记录标识，共享原journal，不另造零计数日志。环境缺失时attempt传--task-id，新计划填写conversation_task_id。

history/history_evidence保留资产旧历史，默认不扣当前额度；仅显式history_task_id等于当前真实对话时扣减。旧日志的未标归属调用由执行者查本地证据，用bind-task --journal <日志> --job <工作项> --task-id <真实原对话ID> --reason <本地记录路径及依据>追加一次原任务绑定，不重复改写。已记录不同来源任务时不得强行合并归属。原生人物入景台账按同一规则记录实际对话ID和本任务计数，旧资产历史单列。

道具继续用原batch与workflow_state.py；具体命令见[道具计数接续](../../ndc-prop-requirements/references/task-budget.md)。

# NDC 对白：主模型控信息，Gemini 3.8 润色

这是用户于 2026-09-07 选定的默认写作流程。当前窗口模型负责剧情理解、信息控制、完整初稿、每轮润色提示词及结果的信息核对；NovAI `[次]gemini-3.8-flash` 负责语言、互动、情绪和活人感。不要默认切回旧的 Gemini 初稿 → 强模型审核 → Gemini 返修团队。

## 默认入口与范围

- 用户说“写对白”“优化对白”“再润一版”时使用本流程；用户当次指定其他模型或方法时遵从当次要求。
- 单场景直接推进；整 Loop / Unit 按实际播放顺序拆成连续场景包。一个包内的多人互动共同写，下一包承接上一包定下的事实和情绪。
- Talk、Opening、Expose、过场及 Repeat 的文字创作使用本流程；谜题、State、Repeat 路由、ID 和配置仍遵守各自专用规范。本 skill 不重设计这些结构。
- `.agents/skills/team-dialogue/SKILL.md` 的旧团队全流程仅在用户明确要求团队审查时启用。不要为普通写作加载并复制整套旧审查清单、启动多名审查员或内容总监。

## 1. 当前窗口模型先控信息并写初稿

读取仓库 `AGENTS.md`、`canon_manifest.json`、`docs/游戏系统/核心玩法/对话与证词系统.md`，从 Manifest 定位目标版本的大纲、State、成稿及人物档案。按任务范围读取相邻场景和旧出场记录；不凭目录名认定最新版，不把试验版当正式版本。写 Expose 时另读指证系统规范；编辑正式对白时另读适用的 dialogue 规则和 MD 格式规范。

用简短的信息控制说明记录：

- 本场从哪里接入、要发生什么、结束后往哪里走。
- 出场人物此刻的目的、关系、称谓、情绪余波；分别已知什么、何时才会知道什么。
- 必须传达的事实、证词及关键限定词；禁止新增或提前说出的事实。保密信息只以必要的禁区描述交给润色模型，不把后续真相整段灌入。
- 必经与可选路径、可跳过/可换序的分支、入口和出口；哪些内容必须在必经路径独立交代。
- 不可改的名称、数值、口令、结构标记、获取指令、路由及证据对应关系。事实须保持语义，只有确需逐字一致的内容才锁定原文。

信息说明可以很短，不为小场景制作全套大型账本。未知事实不让模型补猜；上游缺项影响写作时只澄清必要问题。

**初稿必须是当前窗口模型写出的完整对白，不是只有情节提纲。** 人物先有目的、注意力和自然反应，再传递信息；避免为了控信息写成逐条宣读和整齐问答。若用户交来待改稿，主模型先核对、修整信息边界，用该稿作为工作初稿，不为形式要求另写一份。

## 2. 情感效果是每轮核心需求

每轮提示词开头单列“本轮核心效果”，保留用户原话，再由当前窗口模型具体化：作用于谁、在哪一段、希望玩家感到什么、强度以及需要保留的分寸。磕点、幽默、压抑、疏离等与剧情目标一起指导创作，不能被放到末尾当可有可无的修饰。

- 用户没指定时不默认所有对白都要磕点、搞笑或互怼。
- 用户说“更强一些”时改变互动和连续几轮的情绪推进，不只是加词、加语气词或堆省略号。不要规定每句都要俏皮、每轮都要分胜负。
- 角色关系和知识边界仍须成立；指定情绪不是新增过往、恋爱关系或证据事实的授权。真实冲突才说明，不用假想冲突弱化用户想要的效果。
- 用户喜欢的句子和效果作为后续“保留项”，不拿主模型个人风格偏好覆盖用户判断。

## 3. 当前窗口模型编写完整润色提示词

读取 [提示词模板](references/polish-prompt.md) 和 [Nyra 全文](references/nyra-living-dialogue.md)。由当前窗口模型填入本轮内容，组装为 UTF-8 文件；不让操作员代写、压缩或改动提示词。

每次调用都实际附上：核心情感目标、用户新反馈和保留项、信息控制说明、完整工作初稿、输出格式、Nyra 全文。不能只给本地路径让远端模型“去读”，也不只附风格摘要。

默认采用此次试验中的“重写级润色”：允许重写台词、接话顺序、节奏和笑点；初稿是材料，不是必须模仿的范文。不额外塞主模型写的示范改句，不用固定轮次或句数限制创作。允许调整的是块内表达；游戏结构、知识获得顺序和必需事实不随之改变。

Nyra 文档是对白风格指导：其中“用户/消息”指角色交谈，“不要机械提供选项”不删除游戏分支，“允许漏一点”不删除必要信息。文中的现代聊天例句不移植为时代台词；用户明确要求的情感强度优先于通用风格建议。

## 4. 调用 NovAI

读取并复用 [novai-gemini](../novai-gemini/SKILL.md) 的持久任务脚本，不另造 API 客户端。默认模型必须显式传入完整名称 `[次]gemini-3.8-flash`，不使用 `latest` 或无前缀别名，不静默降级。

初稿、信息说明和逐轮提示词放项目外的 `$CODEX_HOME/novai-gemini/experiments/<task-id>/`（未设置时使用用户主目录下 `.codex`）。每轮使用唯一任务 ID；脚本自行保存输入快照、原始结果和使用量。

从仓库根执行，替换尖括号内的值后运行：

```powershell
python -X utf8 -B .codex/skills/novai-gemini/scripts/gemini_job.py submit --run-id <unique-round-id> --prompt-file "<absolute-prompt-path>" --model "[次]gemini-3.8-flash" --timeout 300
python -X utf8 -B .codex/skills/novai-gemini/scripts/gemini_job.py status --run-id <same-round-id>
python -X utf8 -B .codex/skills/novai-gemini/scripts/gemini_job.py result --run-id <same-round-id>
```

提交一次后只查原任务，稀疏轮询并告知真实进展。`running` 不等于失败；`failed/uncertain` 按调用 skill 处理，不自动换 ID 重试。脚本返回 `succeeded` 仍须看正文：模型停用、升级提示和拒绝服务文本不算对白成功。

**调用操作员只执行命令，不做创作判断。** 一次固定调用由主模型直接执行即可，不为换模型额外开代理。确有可独立并行的操作工作时，按 `AGENTS.md` 使用 `gpt-5.6-sol` / `medium` / `fork_turns="none"` 的轻量操作员，给它精确路径、模型、run ID 和输出责任，不传整段会话历史。用户可指定其他执行模型；执行模型不改变 API 中显式指定的 Gemini 模型。不要声称仅因换操作员就必然节省固定比例成本。

## 5. 核对信息并交稿

主模型做简短的事实与结构核对：有没有新增事实、丢失限定词、提前泄密、破坏关系状态、分支依赖或剧情接缝；与证据、证词、指证步骤的对应是否保持。对照用户核心效果判断，不把个人审美当否决理由，不默认另开团队审查。

保留 Gemini 的原始 `answer.md`。若确需修事实，最小修正另存交付稿并说明；涉及一段互动的改写时由主模型写定向返修提示词，再走相同 Gemini 流程。不要整段重写回主模型声调后仍称“Gemini 原稿”。

展示用户要求的对白和可读文件链接，通常以润色稿为主、初稿供比较，不先丢一份长审查报告。失败时说明没有拿到有效对白，不冒充指定模型写出替代稿。

## 6. 多轮仍走相同流程

用户每次提出返修：当前窗口模型理解新反馈 → 更新核心效果、保留项与信息说明 → 必要时调整工作稿 → 编写新一轮完整提示词 → 同一 Gemini 3.8 模型润色 → 核对信息并展示。

以上一轮用户选定的版本为底稿；每次调用是新请求上下文，输入必要材料，不附所有失败版本或整段聊天。此前情感要求持续有效，用户的新指示覆盖冲突的旧要求。不要每轮自动退回最初版本。

一次“试试/润一下/再改一版”默认提交一轮；用户授权多轮时按约定轮次或完成条件推进。不因模型版本更新、主模型个人不喜欢或 API 超时自行追加对比试验。必要返修遵守已有授权，已授权的下一轮不重复求确认。

## 文件落地边界

本流程的中间稿与 API 原文不是正式剧情批准。项目对白修改遵循 `AGENTS.md` 的举例确认；已确认的修改不重复询问。正式 Unit1 按现行完整台本和 Phase 1/2 规范落地，其他正式/试验版本按 Manifest 和任务授权落地。除非用户明确要求，不同步 JSON、预览配置或 Unity，不调整 ID、路由、State 和证据。

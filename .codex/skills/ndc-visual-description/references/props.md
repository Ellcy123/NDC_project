# 道具：可见物理面、状态与承托

## 描述设计

先明确本次是场景内物件、普通详情图、容器入口/内部还是图标，再决定视角与信息量。遵循主 Skill 的角色排除、容器展示、来源、材质和运行时合同；本 Skill 不新设统一的容器链或游戏交互规则。

描述重点：
- 物件身份及有来源的识别特征；
- 当前开/闭、折叠/展开、完整/破损等单一状态；
- 镜头实际可见的顶面、侧面、边缘、厚度、开口或内部；
- 承托表面、接触、朝向、与邻近物的尺度和遮挡；
- 该资产用途确实需要入画的文字/符号与可读程度。

## 从剧情到物体

“能证明凶手身份的账本”不等于翻开账本或显示凶手名字；“死者珍爱的戒指”不等于额外刻字、血迹或破损。保留事实背景，直接描述已有批准外形与本帧状态。

“某人递交文件”若进入禁止人物出镜的道具模块，应按已有剧情状态与承托规则转译为文件的可见前/后状态。不能自行加入手、手套、人物倒影，也不能删掉持物者后留下悬空道具；交接的获得次序仍留在非图像上下文。

## 可见面与信息量

封闭的不透明盒子不能同时展示内部戒指。写清闭盒的可见顶面、侧面、锁扣与桌面接触；内容物放在独立获准的打开态/详情视图。NDC 主道具流程规定容器内部进入 Type 7 二级菜单时继续遵守，不擅自改为基础场景打开态。

透视中的纸张可只露纸边、厚度或部分封面。场景 Map 识别类别与详情 Big 读取信息不是同一目标；不能为读清文字强行放大、竖立、转正。确实依赖图像解谜的文字/图案应保留准确内容与可用的显示尺度，其展示冲突交回主流程处理，不默默删掉。

“语义母版须完整核对”不等于最终画面所有文字必须无遮挡；批准的自然叠放与局部遮挡继续有效。

## 检查点

从当前视点能看到这些面吗？物体是否靠真实表面承托？是否为了剧情意义增加无依据损伤/标记/内容？外观参考是否误把镜头转成产品正面展示？必要文字是否有来源，是否与本次图像用途匹配？不要用“重要证据、真实可信”等抽象标签代替这些检查。

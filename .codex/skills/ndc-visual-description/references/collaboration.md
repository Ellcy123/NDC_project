# 协作与交接

## 所有权

主 Skill 持有任务范围、来源权威、模型/工具、提示格式、重试预算、像素/坐标锁定、运行时合同及最终验收。本辅助 Skill 持有可见描述转译、冲突检查和与描述同源的视觉检查建议。不反向调用主 Skill，不派发子任务，不形成互相递归加载。

没有主 Skill 的独立调用仅完成描述或审查；不因生成一段提示词就获得生图权限。仅维护本 Skill 也不启动场景/角色生产。

## 接入时机

以 [生产介入设计](intervention.md) 的两个必需检查点为准：A 在布局/姿势定稿前，B 在最终模型输入组装后；下列条目说明如何复用已有流程。

- 编写/修改图像提示词之前，输入当前需求与锁定参考；
- 接收上游 handoff 时检查画面约束是否仍一致，沿用已有分析，不重复造档；
- 候选与意图不符时，先诊断描述、参考及验收的冲突，再交回原流程处理。
- 单纯复用、裁切已批准资产或执行哈希复制不重做创作描述。局部编辑只分析授权区域与保持项。
- 提示文本、相关参考角色、机位/状态或验收要求发生实质变化时，更新受影响的分析；字节复制不使其失效。

## 输入：已有资料足够就直接工作

至少需要当前图像任务与可推导的观察方向。复杂任务沿用资产 ID/Unit、需求来源、叙事事实、当前状态、参考图及各自职责、已批准提示/约束、修改范围、主 Skill 原生格式。只读取涉及本次画面的资料；不强制另建清单或重复提供已存在输入。

如果只有模糊的故事句子：先说明哪些内容缺少视觉定义；可以提出带依据的选择，不把自己的选择升级为用户要求。关键机位或剧情事实冲突且无法从来源决定时，再请求一个必要决定。

## 输出：画面描述与非生成上下文分开

简单任务可直接输出两段：“可复制画面描述”“必要保持项”。

复杂任务可使用下列简短结构，写入主 Skill 现有过程记录，不要求单独 JSON：
- **画面任务/来源**：资产、当前状态、主流程及来源文件/位置；没有文件时写用户本轮要求，不能编造。
- **观察与可见边界**：视点、朝向、画面范围和合理遮挡。
- **需求映射**：事实或目的 → 本帧可见表现；不入画的内容及理由。
- **模型提交文本**：纯粹描述目标画面，附必要参考职责与保持项。不要把整个剧情解释、诊断报告、被删词清单一起发给图像模型。
- **参考职责**：沿用主 Skill 原有图片顺序，标记每图负责什么/不继承什么。
- **验收依据**：可见要求、来源、硬约束/设计目标、检查方式及仍须独立取得的证据。
- **结论**：可交回主流程 / 需修订描述 / 存在需决定的关键冲突。该结论不等于图片视觉 PASS，也不替代主流程门禁。

严格区分“采用了错误的验收标准”与“生成真的偏离了有效要求”。自拟目标若与机位冲突，应留痕修订并重新核对下游合同；不覆盖历史失败报告，不为了迁就候选而改掉有来源的硬约束。

对已批准逐字提示，只给原句定位、冲突原因和最小修改稿；由原审批规则决定是否可替换。主 Skill 的专门门禁不能被本 Skill 隐式豁免；若某门禁要求在当前镜头不可见的内容，应定位到适用阶段/独立证据或请求修订，不能静默绕过。

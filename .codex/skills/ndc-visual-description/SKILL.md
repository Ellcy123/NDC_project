# NDC 画面可见内容约束

把需求转成“这张图实际要看见什么”，再交给对应生产 Skill。剧情负责解释目的与事实；最终图像描述负责规定镜头里能呈现的内容。保留必要的时代、身份、地点和状态信息，不把叙事句子直接变成出镜要求。

独立使用可审查一段提示词；协作时按下述介入点执行，防止正确意图在白模、提示拼装或参考选择中被改写。纯复用、复制、哈希核验不需要重新走描述流程。本 Skill 不调用生图或 Photoshop，不更换模型，不重置重试次数，也不替代主 Skill 的交付验收。

## 细节控制协作

对新生成、提示修订或可见细节缺陷，读取独立辅助 Skill [art-detail-control](../art-detail-control/SKILL.md)，在下述 A/视觉设计点确定“必须保留 → 可省略/归并 → 目标形态 → 检查位置”，在 B/实际提交点核对真正的提示与参考是否仍符合安排。普通室内优先结构、重复陈设归并与共同光照；外景/大空间按实际距离控制信息省略、空气透视、轮廓与云体节奏。角色、道具和局部编辑选对应分支，不统一磨平或加雾。

候选审查复用主流程整图/展示尺寸/原像素证据，区分内容、轮廓、体积、对比、空间层次、表面纹理问题，写明位置与原因。细节辅助检查不替代既有风格/纹理/技术门禁，不改变锁定提示、身份、必要信息或蒙版权限，不增加重试和审批步骤。主流程继续持有提交与交付责任；纯复制/批准资产复用不重新设计。本协作单向读取细节 Skill，不互相递归调用。

## 什么时候介入

**两个必需检查点，其他环节按变化和缺陷触发。** 简单任务可在同一次思考/输出中完成两个检查点，不增加用户审批或重复文件。

1. **视觉设计前**：主 Skill 已解析需求、来源、用途与参考后，且尚未制定白模姿势、站位坐标、场景布局或道具摆位时，先确定本帧镜头、可见目标、合理遮挡与上下文边界。没有参考则按已知需求分析，不伪装看过图片。
2. **实际提交前**：主 Skill 已拼好最终提示、图片顺序及职责、裁切/蒙版与原生参数后，检查这一份真正会发给模型的输入。不能只检查早期草稿；下游补入的“微笑”“正面细节”“全文可读”等文字和参考也可能重新引入冲突。有未解决的实质矛盾先修输入，不消耗一次生成去试错。
3. **出图偏差时**：主 Skill 检查第一张结果及后续新缺陷时，复用实际整图/局部审阅证据，判断是意图不清、组装冲突、模型执行偏差、后处理变化还是验收依据错误；不机械追加否定词或直接用 PS 救图。
4. **实质变化后**：镜头、裁切、可见状态、角色动作、参考职责或有效验收要求改变时，重新检查受影响的项。下游只做保持画面意图的复制/规范化时，不重跑完整描述分析；图像本身的技术和视觉检查照常由主 Skill 执行。

各类生产的具体插入位置、提交检查与缺陷路由见 [生产介入设计](references/intervention.md)。

## 先选分支

- **角色**：读 [角色：朝向、可见表演与投影](references/characters.md)。含白模、人物入景、肖像、表情及角色卡各视图。
- **场景**：读 [场景：镜头、空间与状态](references/scenes.md)。含空场景、同场景状态变化与场景局部。
- **道具**：读 [道具：可见物理面、状态与承托](references/props.md)。含证据、容器、Map/Big/详情图。
- 混合画面只组合实际涉及的分支；由一个主 Skill 管理同一镜头、尺度、遮挡和交付状态。
- 对接其他 Skill 时读 [协作与交接](references/collaboration.md)；需要判断边界时读 [正反案例](references/examples.md)。

## 核心判断

1. **锁定画面任务与镜头。** 先确定资产用途、单帧/分视图、视点、可见方向、裁切和本帧状态。沿用用户与主 Skill 已批准的镜头、来源和风格；有完整输入时不要重复提问。
2. **逐条拆分信息。** 将需求中的信息分别记为“画面可见”“上下文事实”“本镜头不可见/被遮挡”“冲突或待决定”。这是工作分析，不是必须全部贴入最终提示词的标签。
3. **把目的转成可见表现。** 为需要画面传达的动作、情绪、环境状态指定可见载体；对没有明确视觉证据的故事事实保留上下文。合理的轻微动作可作为注明的设计选择，不能擅自补出凶器、血迹、关键证据、新人物或新剧情状态。
4. **按可见性删减冲突描述。** 背面镜头不同时要求直接看清正面表情；封闭不透明物不同时展示内部；远景不同时要求未经授权的细小文字特写。不要把删去的描述重新堆进一长串否定词中。必要排除条件与工具原生参数仍保留。
5. **核对参考角色。** 给每张图标明身份、姿势、机位/空间、材质/风格或编辑底图等作用。角色卡正脸不自动成为本帧朝向，产品正面图不自动改变场景透视。多个参考作用冲突时先解决描述/参考分工，不把所有图笼统要求为“完全一致”。
6. **核对约束是否互相可实现。** 检查动作与接触、空间与遮挡、文字可读性与视距、机位与可见面。明确用户要求优先；不能为暴露信息擅自转身、开盖、移机位、透明化或改变构图。只有影响身份/剧情/锁定镜头且无法可靠推导的冲突才请求决定。
7. **写短而具体的画面描述。** 通常按“镜头/画面范围 → 主体可见状态 → 空间/动作/接触关系 → 必要材质光照 → 保持项”组织。可理解的自然句优先，长度按任务需要；不强迫固定词数、JSON、每图独立报告或额外审批。
8. **让验收与描述同源。** 对每个关键可见要求说明看哪里、比较什么。区分用户/批准图的硬约束、技术硬约束和自行提出的构图目标。未批准的某个像素点、角度或脚距不能自动成为拒收依据；明确坐标锁和工程约束仍严格执行。没有查看图像时只能报告描述检查，不能给视觉 PASS。

人物入景在主流程第一次全场预演中同时判断交流关系、动作自然度、真实承重与环境受力。动作语义正确不保证身体自然，数值或区域覆盖通过也不保证视觉接触；具体判断见角色分支，复用主流程当前预览与审阅，不另设报告或审批。

## 特别容易误用的地方

- “剧情转视觉”不是删除叙事事实，而是分离给策划/执行者的上下文和给图像模型的画面任务。需要直接入画的招牌、文字、符号仍保留准确内容与来源。
- 正面肖像和表情资产应保留可见的面部描述；背影也可通过头部朝向、肩背与动作表达情绪。“表情”“神态”“故事”不是全局禁词。
- 侧视的双腿、重叠道具与远近家具按镜头投影判断。真实空间分离不等于画面横向分离；本 Skill 不负责从一张图推断精确三维数值。
- **生产证据与展示图分开。** 正式镜头允许合理遮挡；主 Skill 若要求完整人体、容器内容或语义母版证据，应单独准备对应视图/组件。不能为交付画面看不见的部位捏造验收通过，也不能把所有隐藏部分强迫露到同一张图里。
- 锁定/逐字批准的提示词不能被自动重写。输出冲突定位和最小修改建议，交回主流程；保留原文、版本与批准关系。
- 已有失败候选先检查“需求 → 画面描述 → 参考作用 → 验收依据”的一致性，再判断模型偏差或后期修复。支撑、姿势与解剖已成立的比例/位置错误可交给主 Skill 已授权的 PS 统一缩放/平移；软物接触错误可交给其有界交互修订路线。语义、视角或解剖冲突不能靠盲目变形解决。

## 最小交付

简单任务直接给可复制画面描述及必要保持项。复杂/协作任务再附：
- 来源/上下文与可见表现的对应关系；
- 已解决冲突及仍需决定的事项；
- 每张参考的职责；
- 关键可见验收点与主 Skill 必须保留的技术要求。

沿用主 Skill 的原生提示格式、输出目录与报告；完整交接约定见 [协作与交接](references/collaboration.md)。检查完成只表示描述可提交给主流程，不表示生成成功或资产可交付。

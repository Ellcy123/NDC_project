# 《摩登迷城》产品体验报告

> 分析范围：仅从玩法与产品体验角度分析

## 1. 结论摘要

整体而言，《摩登迷城》第一章已经呈现出完成度较高、方向明确的黑色电影式 2D 点触叙事推理 Demo；但作为解谜推理类视觉小说，其推理深度、叙事张力与角色关系铺垫仍显不足。

产品辨识度不仅来自单张插画，更来自“场景调查 → 对话记录 → 证据／证词整理 → 矛盾指认”的完整闭环。玩家在 Blue Moon 酒吧及后台空间中反复走访人物，并借助笔记本把零散信息组织成可验证的判断。美术、构图、色彩与案件氛围已经具备可用于 Steam 商店页展示的产品识别度。

角色对话均配有动画与标准英文配音，口型和文本的契合度较高，体现出扎实的研发执行能力。当前最需要提升的并非基础表现力，而是推理与叙事逻辑、文本质量、信息可读性，以及推理反馈的可解释性。

笔记本同时承载人物、物证、线索、证词、地图和对话记录等多个信息层级，单屏信息密度偏高；部分关键操作结果，例如证据是否匹配、错误选择的具体原因和下一步调查目标，仍需要更强的即时反馈。若首章目标是让玩家相信“我是在推理，而不是在试答案”，建议优先打磨推理界面、线索状态表达、导航提示与本地化一致性。

综合建议：维持 Demo／首章公开测试计划；先完成 P0 发布验证与 P1 核心体验修复，再扩大测试规模。当前产品特征可概括为：强风格、强闭环，信息架构仍需一轮系统性打磨。

## 2. 核心循环与推理设计

### 优点

- 调查行为有明确产出：点击场景热点并非只触发氛围文本，而会进入人物、物证、证词与笔记本状态，交互结果能够积累为案件信息。
- “谁在撒谎？”指认页把人物选择与证据选择放在同一张纸面上，符合侦探主题，也让玩家产生整理案卷、验证判断的操作感。
- 对话记录、人物关系、地图与物证并存，已经具备支撑多案件、长线叙事的结构基础。

### 问题与建议

- 第一章以 2D 场景搜证为主，且大部分调查采用强引导设计。全章较接近“解谜”的 Rosa 密码锁，也只是直接抄录线索中的数字，实际推理门槛有限。
- “点击找线索”几乎不要求玩家进行信息加工；案件时间线与人物关系较简单，尚未形成推理类作品应有的思考压力和组合判断。
- 建议提高关键推理节点的信息组合要求，让玩家至少需要对照证词、物证、时间或人物关系中的两个维度，才能形成稳定判断。
- 当前红色失败提示能够表达“选择错误”，却无法说明究竟是证据不对、人物不对，还是指认顺序不对。失败反馈应明确错误发生在哪个判断维度，同时避免直接泄露答案。
- 对人物头像、证词条目和地图节点统一增加“新内容／已读／已验证”三态；允许多次尝试的指认环节应记录已经排除的组合。
- 已完成对话重复点开后缺少立即返回选项，玩家必须再次完成整段对话才能退出。建议再次进入时提供清晰的返回选项，并保留继续回看整段内容的能力。

## 3. 剧情叙事、角色与节奏

### 优点

- 命案现场、酒吧账本、处方单、后台化妆间等物件共同构成了有质感的黑色电影语境；场景不是抽象菜单，而是能够被玩家记住的叙事地点。
- 角色通过半身立绘与头像切换表达情绪。Zack Brennan 的主视角稳定，Vivian Gray、Rosa Martinez、Tommy Connelly 等角色在视觉上能够快速区分。
- 过场使用胶片边框和高反差画面，与主场景的插画质感保持一致。

### 问题与建议

- 第一章剧情整体较为平稳，人物设定存在一定类型化倾向，几名嫌疑人的作案动机主要停留在缺钱、情感背叛等表层原因。
- 关键人物关系铺垫不足。从逐一指证证人到最终破案，情感冲击、人物立场变化和反转力度均未充分释放。
- 建议在不提前破梗的前提下，增加关系矛盾的前置细节与互相印证，让后续指认既能成立，也能重新解释玩家此前见过的行为。
- 在每段关键对话结束后提供微型目标更新，或在场景中保留明确的“可再次询问”标识。
- 章节结束时展示本案已收集物证数、已核实证词数与仍未解决的问题，为玩家提供阶段性成就感和后续期待。

## 4. 场景调查与导航

### 优点

- 酒吧大厅、舞台、走廊、化妆间、会客室等场景在材质、灯光和门牌上具有较强方向感；红地毯、金色装饰和绿黑墙面形成了统一的时代风格。
- “酒吧大厅”“化妆间”“Webb 会客室”等地点牌有助于玩家建立空间记忆。

### 问题与建议

- 返回按钮、房间出口与当前可调查热点在不同场景中的视觉权重不一致。建议统一交互图标、悬停高亮和可离开区域的鼠标反馈。
- 房间是否已取得全部证据，主要依赖右上角放大镜是否显示勾选，提示强度不足；已调查房间后续出现新增证据时，玩家也容易忽略状态变化。
- 让地图节点与房间门牌互相联动：点击地图节点时显示未完成调查项；从场景返回地图时保留上次焦点。
- 对已经调查但出现新增内容的房间，使用独立于“完成勾选”的新增标记，避免完成态覆盖更新态。

## 5. UI/UX 与可读性

### 优点

- 笔记本的视觉隐喻统一：夹板、打孔纸、便笺、图钉和红线都在服务“办案桌”的产品想象。
- 调查分析页把对话记录与人物页并列，符合玩家回查证词和比对说法的实际需求。

### P0／P1 问题与建议

- P0｜可读性风险：证据选择页右侧多列卡片与底部多条证词同时出现，部分文字偏小；在掌机级屏幕（如 Steam Deck）上可能进一步降低可读性。建议提供 UI 缩放、字体大小和高对比模式，并确保鼠标悬停能够放大全文。
- P1｜信息架构：物品、线索、证词、人物和地图虽以图标或标签区分，但未读、新增、已验证状态不够醒目。建议增加颜色之外的图形标记，并提供统一筛选栏。
- P1｜反馈一致性：部分按钮使用红色文字或红色底，部分返回按钮显示英文“BACK”，地点牌与系统提示则使用中文。建议建立覆盖按钮、错误、确认与返回行为的 UI 词典。
- P1｜输入可发现性：画面左上已经出现 `[TAB]` 提示，但核心快捷键与鼠标操作缺少首次进入时的集中说明。建议在首案前 30 秒加入一次可跳过的操作引导。

## 6. 美术、镜头与音频呈现

- 美术完成度是 Demo 的核心竞争力。厚涂／版画式线条、红黑绿主色、局部金色高光与戏剧化灯光共同建立了稳定的黑色电影识别度。
- 命案现场的尸体构图、舞台帷幕、化妆镜灯泡、埃及风壁画、酒吧海报和账本等细节，形成了能够被玩家回忆的环境叙事。
- 镜头从横向场景调查切入纸面证据大图，再转入黑场过场，节奏层次清晰。角色动画、英文配音和口型匹配进一步提高了对话呈现的完成度。
- 研发阶段仍需重点检查暗部可见度：多处黑场、走廊和黑底证据弹窗中，文字或物件与背景亮度接近。建议为关键交互物增加轮廓、局部补光或色盲友好的形状标记。

## 7. 性能与稳定性

建议围绕以下场景建立专项验证清单：

- 在 1080p、1440p、窗口模式、全屏模式、Steam Deck 或低配显卡环境下，验证帧率、内存峰值、文字缩放与界面适配。
- 连续切换房间、反复打开笔记本以及快速跳过对话后，验证调查状态、对话状态和界面状态是否保持一致。
- 中途退出、读档、重复进入已完成证据以及错误指认后，验证流程恢复是否正确。当前已经出现中途退出后无法继续下一步对话，以及存档状态回退的情况，应列为发布前重点排查项。

## 8. 本地化与文本质量

建议建立统一术语表，并在人物页、对话记录、地图、物证页和指认页之间进行交叉校验，确保人物名、地点名、物证名、按钮文案及系统提示完全一致。中英文混用应限定在明确的品牌名、键位提示或风格化内容中，避免同一功能在不同页面出现多种表达。

## 9. 研发问题优先级

以下优先级用于安排发布验证与公开测试前的体验修复，不代表内容扩展阶段的最终排期。

### P0：发布前必须验证

1. 推理与叙事框架：重新审视第一章的推理密度、信息交叉与关系铺垫，确保玩家依靠判断推进，而非依赖试错。
2. 指认规则与失败反馈：验证错误反馈能否解释“为什么错”以及“下一步应检查什么”，同时避免直接泄露答案。
3. 关键信息可读性：验证关键证据、证词和调查分析文字在 1080p、窗口模式与掌机屏幕上的可读性。
4. 状态与存读档一致性：验证退出、读档和重复调查后，对话、物证、地图与流程状态是否一致。

### P1：建议首轮公开测试前完成

1. 笔记本增加未读、新增、已验证、已排除状态，并提供统一筛选。
2. 统一返回、悬停、可交互热点与地点导航的视觉反馈。
3. 增加对话历史、逐句回看、自动播放速度与快速跳过保护。
4. 提供案件总结、收集统计、未解问题与下一步目标。

### P2：内容扩展阶段推进

1. 增加时间线视图、人物关系图与证据卡片互链。
2. 在地图上提示已调查房间中仍存在的未完成项或新增内容。
3. 为关键证据提供可选放大、旋转或局部观察，提升点触调查的参与感。
4. 增加高对比、色盲标记、字体缩放、减少闪烁和文字背景透明度调节等无障碍选项。

## 最终建议

先修复推理反馈、信息状态和存读档一致性，再扩展时间线、人物关系图与证据观察玩法。首章公开测试的核心目标，应是让玩家清楚理解自己为什么推对或推错，并确信案件结论来自推理，而不是反复试答案。

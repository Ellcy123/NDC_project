## 新电脑首次配置

先拉取两个仓库，按照 [脚本依赖说明](../production/art_pipeline/dependencies.md) 准备 Python 环境。项目自有脚本必须连同 Skill 进 Git；不要把个人工具目录、临时工作区中的脚本或个人 Python 安装路径写成团队运行前提。Python/FFmpeg 等第三方软件按依赖说明安装，虚拟环境、密钥和过程文件不进 Git。

从任一仓库根目录执行一次配置。以下三个地址只是示例，请替换为自己电脑上的真实位置；工作区可选空间充裕的任意磁盘，不要求 C 盘或 D 盘，也不要求两个仓库相邻。

```powershell
python -B scripts/art_pipeline/ndc_art.py configure --planning-root "E:/Design Work/Story" --engine-root "F:/Game/Client" --work-root "G:/Art Scratch"
python -B scripts/art_pipeline/ndc_art.py paths
python -B scripts/art_pipeline/ndc_art.py skill ndc-generate-characters
```

配置命令在两库写入被忽略的 `ndc.local.json`；Git 内仅提供 `ndc.local.example.json` 格式示例。移动任一仓库后重新配置。没有配置时应报出缺少的字段，不能猜测隔壁文件夹或回退到其他人的 D 盘。

两库都带 `scripts/art_pipeline/ndc_art.py`：策划库保存公共实现，工程库保存可随 Git 获取的转接脚本。所有后续命令从当前仓库根目录运行；`skill <名称>` 返回主 `SKILL.md` 及 `skill_root`，`run <名称> <脚本名> ...` 从主 Skill 的 `scripts/` 执行。兼容入口和个人入口只负责定位，不存另一份实现，也不是同事执行所必需的依赖。

环境变量 `NDC_PLANNING_ROOT`、`NDC_ENGINE_ROOT`、`NDC_ART_WORK_ROOT` 优先于本机配置；供脚本会话和自动化临时覆盖。旧 `NDC_ART_PATHS_CONFIG` 只为已有任务/测试显式兼容，新电脑走上述入口。锁定提示词和已完成任务日志不嵌入新机器地址。

## 每次出图

1. 从角色索引确定人物、色版和精确版本。索引的 `unconfirmed` 不是美术批准；使用用户明确指定的版本或可核实批准的原图，不根据文件名、最新日期或提交名推定批准。
2. 在正式 Skill 开始前创建任务。JSON 输出中的 `output` 是这次所有新候选、修图、审核证据和待确认成品的共同根。必要时在其下分目录，不能继续往两个仓库或系统临时目录堆积新过程图。
3. 按具体 Skill 完成艺术和技术检查。通过自检后用 `ready` 标记等待用户，展示具体成品。自检通过不代表用户已经选定。
4. 用户确认具体字节版本后，记录 `approve`。若确认后继续改图，原选择失效，回到 `resume`，再次展示新成品。
5. 在用户已经授权的工程目标目录交付；沿用工程命名、格式、`.meta` 和正式表工作流。此工具不会自动复制或覆盖 Unity 文件。完成实际复制后，用 `record-copy` 校验源和目的 SHA-256。
6. 在任务关闭前，给必须长期保留的高清/可编辑母版标记 `mark-master`，把它独立保存到正式素材库，再登记 `record-copy --kind master`。临时工作区内另一份副本、硬链接都不算长期保存。
7. 成功交付或用户明确放弃后 `close`。工具验证留存副本，然后立即清理该受管任务的 `payload`，仅留小型任务记录、选择/交付哈希和关闭原因。

```powershell
python -B scripts/art_pipeline/ndc_art.py workspace create --name Zack_站姿 --kind character
python -B scripts/art_pipeline/ndc_art.py workspace ready --job <输出的job路径>
python -B scripts/art_pipeline/ndc_art.py workspace approve --job <job> --asset final/zack.png --note "用户确认的具体消息或选择"
# 按已授权目标完成复制后登记；本命令不进行复制：
python -B scripts/art_pipeline/ndc_art.py workspace record-copy --job <job> --source final/zack.png --destination <工程内实际文件> --kind delivery
python -B scripts/art_pipeline/ndc_art.py workspace close --job <job> --result delivered --note "已确认并校验工程交付"
```

有母版时，在 `close` 前使用：

```powershell
python -B scripts/art_pipeline/ndc_art.py workspace mark-master --job <job> --source masters/zack.psd
python -B scripts/art_pipeline/ndc_art.py workspace record-copy --job <job> --source masters/zack.psd --destination <项目外工作区以外的正式母版文件> --kind master
```

失败但仍要返工、被工具故障阻塞、等待用户回复，都属于未结束任务；不得自动归为取消。用户明确取消后才能用 `close --result cancelled --note <用户取消依据>`。关闭后的任务不再就地续写，重新创建任务并引用正式母版和旧任务记录。

## 空间管理

工作区默认总预算 50 GiB，新建任务前至少保留磁盘 10 GiB 可用空间。新建任务先清理已结束且可验证的受管任务；若空间仍不足，停止启动新批次。每个大批次或生成阶段开始前再次查看 `status`，不要把预算检查当成磁盘配额隔离。工具不会终止正在生成的文件，也不能阻止绕过工具直接写盘。

```powershell
python -B scripts/art_pipeline/ndc_art.py workspace status
python -B scripts/art_pipeline/ndc_art.py workspace cleanup
python -B scripts/art_pipeline/ndc_art.py workspace cleanup --apply
```

`cleanup` 默认只预览；`--apply` 也只处理状态已经关闭且有合法记录的 `jobs/<任务>/payload`。工作中、待确认、来源不明、旧任务、迁移备份、角色卡和工程资源一律不进入自动清理。目录链接/Junction、异常文件或失效的交付副本会阻止清理。不要拿一个宽泛的 `output` 或 `Art` 文件夹直接登记为已结束任务。

已有的 `output/multichar_avg`、`image/edit_jobs`、工程 `Art/runninghub` 等含活跃制作。它们保留原地址和原始哈希，不改历史交接文件。后续逐任务确认关闭状态、保留必要母版并验证消费者后再清理，不通过批量改历史引用伪造“已迁移”。
